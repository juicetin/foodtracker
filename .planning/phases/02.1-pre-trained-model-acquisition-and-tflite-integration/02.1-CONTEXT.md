# Phase 02.1: Pre-trained Model Acquisition and TFLite Integration - Context

**Gathered:** 2026-03-13
**Status:** Ready for planning
**Source:** Conversation context (post-Phase 2 verification gap analysis)

<domain>
## Phase Boundary

This phase closes the critical gap discovered during Phase 2 verification: the entire detection pipeline (inferenceRouter, imagePreprocess, DetectionScreen) exists but has no actual ML models to run. Without .tflite files, the pipeline throws "model pack not installed" and nothing can be tested on-device.

This phase acquires pre-trained models that slot into the existing three-stage pipeline (binary gate → detection → classification) with zero custom training. It also wires them into the PackManager system and produces a testable APK build.

</domain>

<decisions>
## Implementation Decisions

### Model Selection (Locked)
- **Stage 1 (Binary gate) + Stage 3 (Classification):** Google AIY Food V1 TFLite model — Apache 2.0 licensed, 2,000+ food classes, already in .tflite format, 224x224 input, ~6MB. Repurpose for binary gate (any class confidence > threshold = food).
- **Stage 2 (Detection):** YOLO26n COCO-pretrained, exported to TFLite via Ultralytics. ~10 food classes (banana, apple, pizza, sandwich, etc.) with bounding boxes. 640x640 input, ~8-12MB.
- No custom training required for v1 — this is a zero-training baseline to unblock on-device testing.

### Integration Approach (Locked)
- Models must work with existing `modelLoader.ts` which expects packs in `installed_packs` table with IDs: `yolo-binary-*`, `yolo-detect-*`, `yolo-classify-*`
- Models must work with existing `inferenceRouter.ts` three-stage pipeline
- Models must be loadable via `react-native-fast-tflite`'s `loadTensorflowModel()`
- Export script `training/export_mobile.py` should be updated or supplemented to handle pre-trained model packaging

### Delivery Mechanism (Locked)
- Bundle models for initial testing (don't require R2 download for v1 build)
- Create model manifest (`model_manifest.json`) compatible with existing PackManager
- APK output named `foodtracker-release.apk` per project convention

### Build Verification (Locked)
- Must produce a working APK that can run the detection pipeline end-to-end on device
- The 4 deferred human verification items from Phase 2 should be testable with this build

### Claude's Discretion
- How to bundle models (asset directory vs packager config vs download-on-first-launch)
- Whether to adapt `export_mobile.py` or create a separate acquisition script
- YOLO26n export details (FP16 quantization, NMS config — existing export script has patterns)
- Whether Google AIY model needs any preprocessing adapter (input format matching)
- Model manifest format details as long as compatible with PackManager

</decisions>

<specifics>
## Specific Ideas

- Google AIY Food V1 direct download: `https://storage.googleapis.com/tfhub-lite-models/google/lite-model/aiy/vision/classifier/food_V1/1.tflite`
- YOLO26n export: `from ultralytics import YOLO; model = YOLO("yolo26n.pt"); model.export(format="tflite")`
- Existing pipeline expects: binary (224px, 2 classes), detect (640px, YOLO boxes), classify (224px, N classes)
- Google AIY model outputs 2,024 food classes — need label mapping file
- COCO food classes available in YOLO26n: banana, apple, sandwich, orange, broccoli, carrot, hot dog, pizza, donut, cake
- `imagePreprocess.ts` already handles resize to model input size and RGB normalization

</specifics>

<deferred>
## Deferred Ideas

- Fine-tuning YOLO26n on Roboflow food-tracker-yolo dataset (~42 food classes) — significant accuracy improvement but requires GPU training time
- Training dedicated binary gate on Food/No-Food dataset (5K images, 2 classes)
- Fine-tuning classification on Food-101 (101 classes, 101K images)
- R2-hosted model pack distribution (currently using bundled approach)
- INT8 quantization for smaller model size (currently FP16)

</deferred>
