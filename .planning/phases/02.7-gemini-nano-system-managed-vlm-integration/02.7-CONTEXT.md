## Phase Boundary

Integrate Gemini Nano (ML Kit GenAI Prompt API, system-managed by AICore) as a Tier 0 food identification path above SmolVLM. Two waves:

- **Wave 1 (spike):** Minimal native Expo module + GeminiNanoTestScreen to evaluate output quality on Pixel 9 Pro. Human checkpoint gates Wave 2.
- **Wave 2 (integration):** GeminiNanoService wired into runVlmIdentification() as primary path; SmolVLM fallback on unsupported/unavailable devices.

<decisions>
## Implementation Decisions

### Wave 1 spike structure
- Write a minimal Expo native module (Kotlin only for Wave 1 Android-first) with two methods: `checkAvailability(): Promise<'available' | 'downloading' | 'not_supported'>` and `identifyFood(imageUri: string, prompt: string): Promise<string>`
- Add a `GeminiNanoTestScreen` accessible from Settings/Debug menu (not the main detection flow)
- Test screen shows: same food photo → Gemini Nano output on left, SmolVLM output on right (or sequential with timestamps)
- The spike is throwaway UI; Wave 2 integration is the permanent work
- Human checkpoint is a required gate: user evaluates quality on Pixel 9 Pro before Wave 2 code is written

### ML Kit GenAI API selection
- Use the **Prompt API** (`play-services-mlkit-genai-prompt`), not the Image Description task API
- Reason: Prompt API allows custom structured prompts — we can ask for JSON output matching VlmFoodResult shape directly. Image Description returns a free-text paragraph requiring additional parsing.
- Prompt API is alpha (since Oct 2025) — expect possible breaking changes. Pin the dependency version.
- Check AICore readiness before every call (OS controls model availability; must handle DOWNLOADING and NOT_SUPPORTED states gracefully)

### Native module scope (Wave 1)
- Minimal but proper: Expo Module API (not bridge/legacy NativeModules)
- Kotlin file: `GeminiNanoModule.kt` — ~80-120 lines
- TypeScript bindings: `geminiNanoModule.ts` — typed wrappers over the native methods
- Just two methods needed for the spike: availability check + inference
- No iOS implementation in Wave 1 (Android-only for the Pixel 9 Pro test)

### Output format from Prompt API
- Prompt Gemini Nano to return JSON matching our existing `VlmFoodResult` shape: `{ dishes: [{ name: string, cuisine?: string, ingredients?: string[], portion_size?: string }] }`
- Parse the JSON response in the TypeScript layer (not Kotlin) — same approach as vlmService's grammar-constrained output
- If JSON parse fails, return `{ dishes: [] }` (same fallback as vlmService)

### Wave 2 integration architecture
- New file: `apps/mobile/src/services/vlm/geminiNanoService.ts` — parallel to vlmService.ts, same public interface: `identify(photoUri, userText?) → Promise<VlmFoodResult>`
- `runVlmIdentification()` in vlmPipeline.ts checks Gemini Nano first:
  ```
  if (await geminiNanoService.isAvailable()) → use Gemini Nano
  else if (vlmService.isReady) → use SmolVLM (existing path)
  else → throw (VLM required, neither available)
  ```
- No model download prompt for Gemini Nano — it's system-managed. If unavailable, fall through to SmolVLM silently.
- Pixel 7 Pro experience: unchanged — Gemini Nano not available on Tensor G2, falls through to SmolVLM as today

### Fallback chain
- Tier 0: Gemini Nano (AICore, system-managed) — Pixel 9 series, Galaxy S25+
- Tier 1: SmolVLM (downloaded pack, llama.rn) — any device with ≥4GB RAM + pack installed
- Hard fail: neither available → show VlmDownloadScreen (existing behavior, unchanged)
- No silent "Food Region" fallback — VLM is required for usable identification (per Phase 02.7 goal and existing architecture)

### Device support (no guessing at runtime)
- Use `checkAvailability()` result to determine Gemini Nano tier — do NOT hardcode device model checks
- Cache availability result per app session (AICore state doesn't change mid-session)
- Log availability to console in dev builds for debugging

### Claude's Discretion
- Exact Kotlin Prompt API session management (session reuse vs. per-call sessions)
- Prompt wording (experiment during spike, lock in Wave 2)
- Whether to show a "Gemini Nano" vs "SmolVLM" indicator in the detection UI (nice-to-have for Wave 2)
- Error retry logic in geminiNanoService (suggest: one silent retry, same as identifyWithRetry in vlmPipeline)
