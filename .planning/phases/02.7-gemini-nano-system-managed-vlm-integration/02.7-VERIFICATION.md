## Architectural Note

The plan was written targeting `runVlmIdentification()` and a SmolVLM fallback. The codebase was refactored prior to Wave 2 execution: SmolVLM was removed entirely and the public API became `scanFood()`. The Wave 2 summary documents this deviation explicitly. Verification assesses the **intent** — Gemini Nano as primary path, graceful fallback on unsupported devices — against the actual implementation, regardless of function name changes. This is the correct interpretation per the verification brief.

### 1. Tier 0 Path on Pixel 9 Pro

**Test:** Install APK on Pixel 9 Pro (locked bootloader, AICore installed). Take a food photo via DetectionScreen > Camera. Wait for scan to complete.
**Expected:** Model badge shows "✦ Gemini Nano" (not "Demo Mode" banner), "Raw Output" button appears, tapping it opens a modal with a JSON string containing a `dishes` array with recognizable food items.
**Why human:** AICore is unavailable on emulator (all calls return 'unavailable'). The Tier 0 code path (`status === 'available'` branch) can only execute on physical Pixel 9 series hardware.

### 2. GeminiNanoTestScreen on Pixel 9 Pro

**Test:** Open ProfileScreen > AI Models > Gemini Nano Test. Observe the AICore Status badge. Pick a food photo from gallery. Tap "Run Test".
**Expected:** AICore Status shows "Available" in green. Run Test returns a JSON string (possibly with surrounding text, possibly clean JSON) within 5 seconds. Response contains identifiable dish names.
**Why human:** Same hardware constraint as above. Emulator shows "Not Supported on This Device" by design — this is the correct emulator behavior.
