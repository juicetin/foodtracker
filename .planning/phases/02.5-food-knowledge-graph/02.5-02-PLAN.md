       - This prevents typos in raw SQL strings across the service

    2. **Create symspellIndex.ts** -- SymSpell fuzzy matcher:
       - Implement `SymSpellIndex` class per the research code example
       - `loadFromDb(db)`: load `symspell_deletes` table into a Map<string, number[]> and dish names from `dish` table
       - `lookup(query, maxResults=5)`: generate deletes of the query string (up to edit distance 2), intersect with the pre-computed map, compute actual Damerau-Levenshtein distance, return sorted by distance
       - Private `generateDeletes(word, maxDist)`: breadth-first character deletion
       - Private `editDistance(a, b)`: Damerau-Levenshtein implementation
       - Normalize all inputs to lowercase with spaces (replace hyphens/underscores)
       - Do NOT use symspell-ex npm package (stale, 250 downloads/week) -- implement the ~150 lines of SymSpell directly. The algorithm is simple and stable.

    3. **Create knowledgeGraphService.ts** -- core KG query service:
       - `open(dbPath)`: open KG SQLite database via `openNutritionDb(dbPath)`, initialize SymSpellIndex from DB
       - `close()`: close DB connection
       - `searchDish(query)`: normalize input (lowercase, replace hyphens/underscores with spaces, trim), then:
         a. Try FTS5 on `dish_fts` (MATCH with prefix: `query*`)
         b. Try FTS5 on `dish_alias_fts` (MATCH with prefix: `query*`), JOIN to dish
         c. Try SymSpell fuzzy match (lookup, get best match, return dish by ID)
         d. Return null if all fail
       - `getCanonicalRecipe(dishId)`: query `recipe` WHERE dish_id=? AND is_canonical=1, return recipe with joined ingredients
       - `getRecipeIngredients(recipeId)`: query `recipe_ingredient` joined with `usda_food` on usda_fdc_id
       - `calculateDishNutrition(className, portionGrams)`:
         a. searchDish(className)
         b. If no dish found, return null
         c. getCanonicalRecipe(dish.id)
         d. If no recipe, return scaleMacros(dish, portionGrams) with source='dish_average' (using dish.avg_* fields)
         e. If recipe found, sum per-ingredient nutrition (quantity_grams/100 * usda calories/protein/carbs/fat), scale to portion, return with source='recipe'
       - `getDishAverages(className)`: searchDish then return dish-level avg macros (for tier 2 fallback)
       - Follow existing NutritionService patterns: raw SQL via op-sqlite execute(), camelCase result mapping

    4. **Write unit tests** using Jest mocks:

       - Test the normalization: "Pad_Thai" -> "pad thai", "Caesar-Salad" -> "caesar salad"
       - Test portion scaling: 300g of a dish with 500g recipe total_weight should scale macros by 300/500
