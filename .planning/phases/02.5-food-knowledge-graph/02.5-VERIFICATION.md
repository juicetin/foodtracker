### Notable Decisions (Phase Context)

- **Plans 04-06 were gap-closure plans** added after initial execution (Plans 01-03) revealed data quality issues: hardcoded 50g quantities, partial parquet loading, and insufficient USDA coverage.
- **MIN_RECIPE_COUNT=10 threshold** introduced in Plan 06 to replace Plan 04's "no cap" approach. The "no cap" plan intent was long-tail coverage; the implementation found that removing the cap produced 1.1M dishes and a 991MB DB. The final threshold of 10 achieves 15K+ dish goal while meeting 70MB constraint.
- **Top-30 ingredient cap per dish** was an unplanned but necessary optimization. Popular dishes like "chili" accumulated 2,400+ unique ingredient strings across hundreds of recipe variations, exploding the recipe_ingredient table to 1.4M rows.
- **SymSpell edit distance effectively 1** (not 2 as specified in Plan 02): the search uses `lookup(normalized, 1)` at DetectionScreen line 86. The DB pre-computes distance-2 deletes, but the runtime query uses maxResults=1. This is a minor spec deviation with no functional impact on common typos.
- **NUT-01 not in REQUIREMENTS.md**: Referenced across five plan frontmatter files but undefined in REQUIREMENTS.md. The code satisfies the inferred intent (real nutrition vs flat-rate proxy).
