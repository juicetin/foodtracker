  </behavior>
  <action>
Create `knowledge-graph/parse_quantities.py` with a `parse_quantity_grams(ingredient_str: str) -> float | None` function.

Implementation approach:
1. Define UNIT_TO_GRAMS conversion table covering: cup (240g water-based, with ingredient-specific overrides for flour=120g, sugar=200g, rice=185g, oil=218g), tablespoon (15g), teaspoon (5g), oz (28.35g), lb (453.6g), kg (1000g), g (1g), ml (1g), liter (1000g).
2. Define COUNT_ITEM_GRAMS for countable items: egg (50g), clove garlic (3g), slice bread (30g), medium onion (110g), medium potato (150g), medium tomato (123g), medium apple (182g), medium banana (118g), stalk celery (40g), sprig (2g), head garlic (50g), bunch herbs (30g), etc.
3. Parse the ingredient string:
   a. Extract the numeric amount using regex (handles "1", "1.5", "1/2", "1 1/2", Unicode fractions, ranges like "2-3")
   b. Extract the unit (match against known units including abbreviations)
   c. Extract the ingredient name (remainder after amount+unit stripping)
   d. If a unit is found, multiply amount by unit-to-grams conversion
   e. If no unit but a countable item is detected, use COUNT_ITEM_GRAMS
   f. For "to taste" / "pinch" / "dash" patterns, return 1.0g
   g. If nothing can be parsed, return None (caller decides fallback)

Do NOT try to handle every edge case -- this runs at build time on 500K recipes. Aim for 70-80% of common patterns parsed correctly; the remaining 20-30% will fall back to the existing 50g default in the caller.

Write tests in `test_parse_quantities.py` FIRST (RED), then implement (GREEN).
