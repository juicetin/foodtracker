## Decisions Made
- **corbt/all-recipes replaces RecipeNLG**: RecipeNLG requires manual website download and its HuggingFace dataset script API is deprecated in modern `datasets` library. all-recipes has 537K recipes in Parquet format, freely downloadable.
- **Embedded USDA data (500 foods)**: Nutrition data hardcoded in build_kg.py rather than downloaded at build time, making the pipeline fully self-contained with zero external API calls.
- **SymSpell edit distance 1**: Edit distance 2 generates O(n^2) deletes per word, which is too expensive for 10K+ dishes with multi-word names. Distance 1 covers single-character typos (80% of common errors) and runs in seconds.
- **Recipe dishes capped at 8000**: Using only the top 8000 dishes with >= 3 recipe occurrences balances coverage (8646 total with curated) against database size (48MB vs 70MB limit).
- **Lightweight ingredient cleaning**: Pre-compiled regex for stripping amounts, units, and modifiers from ingredient strings -- avoids slow parse_ingredient_text() on 537K recipes.

**1. [Rule 3 - Blocking] RecipeNLG unavailable, substituted with all-recipes**
- **Found during:** Task 1 (recipe seeding)
- **Issue:** RecipeNLG requires manual download from recipenlg.cs.put.poznan.pl (not freely available via HuggingFace API). The datasets library deprecated custom loading scripts.
- **Fix:** Used `corbt/all-recipes` (537K recipes, Parquet format) as alternative data source. Same recipe structure (title + ingredients), publicly downloadable via huggingface_hub.

**2. [Rule 1 - Bug] SymSpell edit distance 2 computation was intractably slow**
- **Found during:** Task 1 (SymSpell computation)
- **Issue:** Recursive edit distance 2 generation for 8K+ multi-word dish names caused Python to run for 30+ minutes before being killed.
- **Fix:** Switched to edit distance 1 with per-word BFS delete generation. Also added concatenated-name deletes for compound names. Runs in <1 second.
- **Files modified:** knowledge-graph/build_kg.py
- **Verification:** 320K+ SymSpell entries generated, test passes
- **Committed in:** 0429a773

**3. [Rule 1 - Bug] FTS5 content-sync tables not populated after bulk insert**
- **Found during:** Task 1 (FTS5 testing)
- **Issue:** FTS5 triggers fire on INSERT but the schema.sql CREATE TRIGGER uses IF NOT EXISTS, and bulk data was inserted before FTS rebuild. Content-sync FTS5 tables need explicit rebuild.
- **Fix:** Added FTS5 rebuild step (INSERT INTO fts(fts) VALUES('rebuild')) at end of pipeline.
- **Files modified:** knowledge-graph/build_kg.py
- **Verification:** dish_fts MATCH 'pad thai' returns results, test passes
- **Committed in:** 0429a773

**4. [Rule 3 - Blocking] USDA ingredient linking caused 10+ minute build stall**
- **Found during:** Task 1 (USDA linking step)
- **Issue:** UPDATE recipe_ingredient SET usda_fdc_id WHERE ingredient_name = ? performed full table scan on 506K rows for each of 89K unique ingredient names. No index on ingredient_name caused O(n*m) ~44 billion row comparisons.
- **Fix:** Added CREATE INDEX IF NOT EXISTS idx_tmp_ri_ingname ON recipe_ingredient(ingredient_name) before linking, DROP after. Reduced linking from 10+ minutes to ~2 seconds.
- **Files modified:** knowledge-graph/build_kg.py
- **Verification:** Full build completes in 30 seconds
- **Committed in:** 0429a773

**5. [Rule 1 - Bug] export_mobile.py referenced old schema tables**
