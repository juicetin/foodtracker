**Training configuration adjustments:**

The training script (`train_food2k.py`) does NOT need code changes -- all configuration is via CLI args and the script auto-detects `num_classes` from the ImageFolder structure (it saves the class mapping during training). However, we need to pass the right arguments.

Training adjustments for the larger dataset:
- `--dataset-dir /home/me/media/foodtracker-ml/datasets/merged_v2` -- use the new merged dataset
- `--checkpoint-dir /home/me/media/foodtracker-ml/checkpoints_v2` -- separate from v1 checkpoints
- `--batch-size 128` -- reduce from 256 to 128. With 700+ classes and more images, larger batches may cause OOM on 20GB VRAM. If 128 still OOMs, try 64.
- `--epochs 30` -- same as before (proven)
- Leave frozen-epochs at 5, LR schedule at defaults (proven hyperparameters)

However, the script currently hardcodes `num_classes: 335` in DEFAULT_CONFIG. The ImageFolder auto-detects the correct count, but the model creation uses config["num_classes"]. **Fix needed:** Update train_food2k.py to detect num_classes from the dataset when using ImageFolder format:

After line `train_dataset = datasets.ImageFolder(train_dir, transform=train_transform)`, add:
```python
# Auto-detect num_classes from dataset
detected_classes = len(train_dataset.classes)
if detected_classes != config["num_classes"]:
    logger.info(f"Auto-detected {detected_classes} classes (config had {config['num_classes']}). Using detected count.")
    config["num_classes"] = detected_classes
```

Also add a `--num-classes` CLI arg that defaults to 0 (auto-detect):
```python
parser.add_argument("--num-classes", type=int, default=0, help="Number of classes (0 = auto-detect from dataset)")
```
And in main(), only set config["num_classes"] if non-zero:
```python
if args.num_classes > 0:
    config["num_classes"] = args.num_classes
```

**Run training:**

```bash
cd /home/me/media/foodtracker-ml
source venv/bin/activate
python train_food2k.py \
  --dataset-dir /home/me/media/foodtracker-ml/datasets/merged_v2 \
  --checkpoint-dir /home/me/media/foodtracker-ml/checkpoints_v2 \
  --batch-size 128 \
  --epochs 30 2>&1 | tee training_v2.log
```

This will take approximately 3-4 hours. The script saves checkpoints every 500 steps and at each epoch boundary. It auto-resumes from the latest checkpoint if interrupted.

**If batch_size=128 causes OOM:** Reduce to 64 and increase num_workers to 16 to keep GPU fed. The script's mixed-precision (AMP) training already reduces memory usage.

**Monitor training:** The log file shows per-epoch validation accuracy. We expect:
- Epochs 1-5 (frozen): ~40-55% top-1 (training head only)
- Epochs 6-15 (unfrozen): ~55-65% top-1 (fine-tuning all layers)
- Epochs 16-30: ~65-75% top-1 (convergence)

Target: >70% top-1 validation accuracy. This is harder than the 335-class task (~74%) due to more classes and higher visual similarity within cuisine groups.

**If accuracy plateaus below 65% at epoch 20:** Consider that this may be the limit of EfficientNet-Lite0 at 700+ classes. Per user's Claude's Discretion section, we MAY upgrade to EfficientNet-Lite1 or Lite2 if needed. But try Lite0 first -- it's proven and keeps model size small.
