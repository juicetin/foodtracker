# Phase 2.6: On-Device VLM Integration — Context

## What This Phase Does

Integrates an on-device vision-language model (SmolVLM family via llama.rn) that refines YOLO food identification using multimodal image+text understanding. The VLM acts as the "eyes and ears" while the Knowledge Graph (Phase 2.5) provides the "source of truth" for nutrition data.

## Why It Matters

- YOLO is limited to 241 trained classes — can't identify dishes outside its training set
- Text-only achieves 88.84% accuracy vs image-only 73.60%; dynamic fusion reaches 97.84%
- User free-form text ("big bowl of laksa with extra tofu") is a massively underutilized signal
- VLM can identify ingredients, modifiers, portion hints that YOLO can't
- No existing open-source food tracker uses on-device NLP — this is greenfield

## Critical Finding: ADR-005 VLM Tiers Need Revision

Two of three originally planned models are NOT viable for multimodal GGUF:

| ADR-005 Plan | Reality | Status |
|---|---|---|
| SmolVLM-256M | Q8_0: 175MB model + 104MB mmproj = 279MB. Confirmed in llama.cpp | **Viable** |
| Moondream 0.5B | 0.5B doesn't exist as multimodal GGUF. Moondream2 is 1B, F16 is 2.84GB | **Not viable as specced** |
| Gemma 3n E2B | `Gemma3nForConditionalGeneration` not supported in llama.cpp GGUF conversion | **Not viable** |

**Revised tiers (all SmolVLM family):**

| Tier | Model | Download | RAM | Target |
|---|---|---|---|---|
| Budget | SmolVLM-256M Q8_0 | ~280 MB | ~500 MB | 4 GB RAM |
| Mid-range | SmolVLM-500M | ~500 MB est. | ~1 GB | 6 GB RAM |
| High-end | SmolVLM2-2.2B Q4 | ~1.2 GB est. | ~2 GB | 8 GB+ |

## Existing Infrastructure

### Model Loading (modelLoader.ts)
- Module-level singleton cache: `cachedModelSet: ModelSet | null`
- `ModelSet` type holds two `TFLiteModel` handles (detect + classify) — tightly coupled to react-native-fast-tflite
- VLM needs its own parallel loading infrastructure (GGUF via llama.rn, not TFLite)
- `installed_packs` table and PackManager reusable for VLM download/storage

### Inference Pipeline (inferenceRouter.ts)
- Two-stage: YOLO detect → EfficientNet classify → returns `InferenceResult` with `DetectedItem[]`
- VLM would be Stage 3: async refinement after YOLO results displayed
- `DetectedItem` type (types.ts lines 64-74): has className, confidence, bbox, correctedFrom — needs vlmLabel/vlmConfidence fields

### PackManager (packManager.ts)
- Downloads from R2 via `fetch()` API — **buffers entire download into memory** (`response.arrayBuffer()` line 117)
- **Will OOM on 300MB+ VLM downloads** — needs streaming download
- Pack types: `'nutrition' | 'model'` — needs `'vlm'` added
- Single file per pack — VLMs need paired files (model GGUF + mmproj GGUF)
- No download resume support (HTTP Range headers)

### Text Input UX (ItemDetailSheet.tsx)
- Existing manual correction flow: tap food name → TextInput → save → correctedFrom tracked
- CorrectionStore.getSuggestion() for "Did you mean X?" pills
- No free-form text input for meal description — needs new UI element on DetectionScreen

### Detection UX (DetectionScreen.tsx)
- FlowState: idle → picking → detecting → results
- Results: annotated photo with bounding boxes, detection list, summary bar
- `useDetectionStore` Zustand store: setItems, correctItem, activeItems
- For VLM handoff: need isRefining state, refineItem action, animated label transitions

### App Architecture
- **New Architecture enabled** (`newArchEnabled: true` in app.json) — required by llama.rn v0.10+
- **Dev client builds** (not Expo Go) — required by both react-native-fast-tflite and llama.rn
- No `expo-device` dependency yet — needed for RAM detection

## Framework: llama.rn

**Repository:** github.com/mybigday/llama.rn (v0.10+)

**Core API:**
```typescript
const context = await initLlama({
  model: 'file:///path/to/model.gguf',
  n_ctx: 2048, n_gpu_layers: 99, use_mlock: true,
  ctx_shift: false,  // REQUIRED for multimodal
});
await context.initMultimodal({ path: 'path/to/mmproj.gguf', use_gpu: true });
const result = await context.completion({
  messages: [{
    role: 'user',
    content: [
      { type: 'image_url', image_url: { url: 'file:///path/to/image.jpg' } },
      { type: 'text', text: 'What food is in this image?' }
    ]
  }],
  response_format: { type: 'json_schema', json_schema: { ... } }  // grammar-constrained
}, callback);
await context.release();
```

**Key capabilities:**
- Grammar-constrained JSON output (GBNF) — structure always valid
- Multimodal via mmproj (image + text) — images as file paths or base64 data URIs
- Dynamic load/unload — essential for coexisting with YOLO pipeline
- Expo compatible via config plugin: `['llama.rn', { enableEntitlements: true, enableOpenCL: true }]`

**Confirmed working multimodal models in llama.cpp:**
- SmolVLM (256M, 500M, full) — officially listed
- SmolVLM2 (2.2B, 256M-Video, 500M-Video) — officially listed
- Moondream2 (1B, April 2025) — officially listed
- Gemma 3 (4B, 12B, 27B) — listed but NOT Gemma 3n
- **NOT working**: Moondream 0.5B (doesn't exist as GGUF), Gemma 3n (architecture unsupported)

**Alternative: react-native-executorch** — v0.8.0 (VLM support) NOT released yet. Not viable.

## Pipeline Design

```
Photo taken
  → YOLO boxes appear instantly (50-80ms)
  → VLM loads (if not cached) + processes image + optional user text (1-3s)
  → VLM produces structured JSON: { dishes: [{ name, cuisine, ingredients, portion_size }] }
  → Match VLM dishes to YOLO bounding boxes
  → Labels upgrade in-place with animation
  → VLM dish names → KG lookup → recipe-based nutrition
  → Fallback: VLM+KG → YOLO+KG → YOLO+flat-rate proxy
```

## Key Decisions Already Made

1. **llama.rn is the framework** — only option with working multimodal VLM today
2. **SmolVLM family for all tiers** — one architecture, predictable scaling
3. **YOLO stays as primary** — instant spatial detection; VLM refines asynchronously
4. **Full image to VLM, not crops** — simpler, lets VLM reason about whole plate
5. **VLM pre-warm on first detection** — load after YOLO results, keep warm during session
6. **Grammar-constrained JSON output** — ensures parseable structured output every time
7. **Two inference engines coexist** — react-native-fast-tflite (YOLO) + llama.rn (VLM)

## Key Risks

1. **Memory pressure** — YOLO models (~20MB) + SmolVLM (~300-500MB context) + app overhead on 4GB devices
2. **Vision encoding latency** — 2-3s for 3B models on mobile; SmolVLM-256M should be faster but no published benchmarks
3. **SmolVLM food accuracy** — trained on general data, not food-specific. May confidently misidentify unfamiliar dishes. Grammar constraints prevent structural errors but not semantic errors.
4. **PackManager OOM** — current `fetch().arrayBuffer()` pattern will crash on 300MB downloads. Must fix before VLM downloads work.
5. **Thermal throttling** — sustained VLM inference on mobile generates heat. Burst-then-sleep pattern needed.
