    **reidentifyService.ts** — Gemini Nano re-scan + KG enrichment:
    - `reidentifyEntry(photoUri: string)`: calls geminiNanoService.identify(photoUri), then for each dish/ingredient in the VlmFoodResult, looks up nutrition via KG searchDish + calculateDishNutrition. Returns enriched MergeCandidate[] with { dishName, cuisine, ingredients: [{ name, amountG, calories, protein, carbs, fat, fiber, source }] }
    - `applyMergeResult(entryId: string, keepItems: MergeItem[])`: deletes all existing ingredients for the entry, then inserts keepItems via addIngredient(), then recalculateEntryTotals(). This is the "Save+Confirm" action.
    - MergeItem type: { id: string; name: string; amountG: number; calories: number; protein: number; carbs: number; fat: number; fiber: number; dishName: string; source: 'existing' | 'new' }
    - Uses getKnowledgeGraphService() for KG lookups (same pattern as FoodSearchScreen)
    - Gemini Nano ONLY per locked decision -- no VLM fallback, no cloud inference. If geminiNanoService.identify() throws, propagate the error to the UI.

    **DraggableItem.tsx** — Draggable card for merge view:
    - Props: { item: MergeItem; onDragStart: () => void; onDragEnd: (side: 'left' | 'right') => void }
    - Uses Gesture.Pan from react-native-gesture-handler
    - Animated horizontal translation via reanimated useAnimatedStyle + useSharedValue
    - Card shows: ingredient name, amount_g, calories, source badge ('existing' gray / 'new' green)
    - When dragged past midpoint of screen, snaps to other column on release
    - Use activeOffsetX: [-10, 10] to require horizontal intent before drag activates (prevents conflict with vertical scroll per project pattern from DiaryScreen)

    **MergeColumn.tsx** — Scrollable column for merge view:
    - Props: { title: string; items: MergeItem[]; side: 'left' | 'right'; onItemDraggedOut: (item: MergeItem) => void; headerColor: string }
    - ScrollView containing DraggableItem cards
    - Header: title + item count
    - Left column: "Discard" with red header
    - Right column: "Keep" with green header
    - Empty state text when column is empty

    **ReidentifyMergeScreen.tsx** — Full-screen diff/merge:
    - Gets entryId from route params
    - On mount: loads current entry data (existing ingredients) into left column ("Previous"), calls reidentifyEntry(photoUri) and puts results into right column ("New — Gemini Nano")
    - While re-scanning: shows ActivityIndicator with "Re-scanning with Gemini Nano..."
    - After scan: two columns side by side (left = previous/discard, right = new/keep)
    - User drags items between columns — each drag is an EditCommand (MoveItemCommand) tracked by useEditSession for undo/redo
    - MoveItemCommand: execute() moves item from source to target array; undo() moves it back
    - Header bar: "Re-identify" title, Undo/Redo buttons (from session), close (X) button
    - Footer bar: "Reset" button (left, outlined) returns to post-scan state (right=new, left=existing); "Save + Confirm" button (right, filled green) calls applyMergeResult with items in keep column
    - On Save+Confirm: navigate back to EntryDetail, which reloads entry from DB
    - On error from Gemini Nano: show Alert with error message, navigate back

    **Navigation wiring:**
    - Add ReidentifyMergeScreen to AppNavigator stack
    - Export from screens/index.ts
    - Update edit/index.ts barrel to include DraggableItem, MergeColumn

    Implementation notes:
    - The merge columns track items in local state (useState arrays), NOT in SQLite. Only Save+Confirm writes to DB.
    - Reset restores the original split (existing items in discard, new items in keep) -- this is the "post-scan original state" per locked decision
    - Drag-and-drop is HORIZONTAL only (left/right) -- items move between columns, not reordered within a column
