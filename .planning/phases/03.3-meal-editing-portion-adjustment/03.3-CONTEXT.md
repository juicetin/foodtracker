# Phase 3.3: Meal Editing + Portion Adjustment - Context

**Gathered:** 2026-03-20
**Status:** Ready for planning

<domain>
## Phase Boundary

Enable users to correct any logged meal — change ingredients, swap items, adjust portions, or re-run Gemini Nano identification. This is the correction/refinement layer on top of the diary.

</domain>

<decisions>
## Implementation Decisions

### Nutrition Recalculation
- Real-time recalculation as user adjusts portions (not batch on Save)
- Each ingredient portion change immediately updates entry totals

### Re-identification UI (Gemini Nano)
- Diff/merge view when user triggers re-identification:
  - Left side = previous results (discard side)
  - Right side = new Gemini Nano results (keep side)
  - Drag-and-drop food items AND individual ingredients between sides
  - Full undo/redo stack until Save+Confirm
  - "Reset" button to return to post-scan original state
- Gemini Nano via AICore ONLY — no VLM fallback, no cloud inference

### Edit History
- Store final state only — no audit trail of changes

### Ingredient Addition
- Search KG/OFF first when adding new ingredients
- Manual macro entry as fallback if not found in KG/OFF

### Claude's Discretion
- Edit view layout and navigation pattern (bottom sheet vs full screen)
- Serving size selector UI (dropdown, slider, or inline picker)
- Undo/redo implementation approach (command pattern vs state snapshots)
- Drag-and-drop implementation (react-native-gesture-handler vs react-native-reanimated)
- How to handle meals with no photo (re-identification not available)

</decisions>

<specifics>
## Specific Ideas

- The diff/merge view for re-identification is the most complex UI in this phase. It should feel like a visual merge tool — clear what's old vs new, easy to cherry-pick.
- Real-time recalculation means every portion slider or input change triggers a total recalc. Debounce if needed for performance.
- The undo/redo stack should be lightweight — this isn't a document editor, just a meal with a few ingredients.

</specifics>
