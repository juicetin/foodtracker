## Human Verification Required

The following behaviors require runtime testing on device/emulator. All code paths are implemented and wired; verification is blocked only by gesture input or device-specific availability.

### 1. KG Portions Populate in ServingSizeSelector

**Test:** Open EntryDetail for a logged meal containing a recognizable ingredient (e.g. "chicken breast"). Tap Edit, then tap the serving size dropdown for that ingredient.
**Expected:** Dropdown shows at least one KG-sourced portion (e.g. "1 breast (174g)") in addition to the common sizes (100g, 1 serving, Custom).
**Why human:** KG portion lookup is async and DB-content-dependent. Code path confirmed but runtime data depends on KG DB population.

### 2. Real-Time Recalculation After Portion Change

**Test:** In edit mode, change an ingredient portion via the selector. Observe entry totals before and after.
**Expected:** Calories, protein, carbs, fat totals update immediately on screen (within ~100ms) without tapping Save.
**Why human:** `recalculateEntryTotals` + `loadEntry` are called in the command but the UI re-render timing requires visual confirmation.

### 3. Pinch-to-Zoom in PhotoViewer

**Test:** Tap a photo on any entry with a photo. In the PhotoViewer, pinch to zoom in, then pan while zoomed.
**Expected:** Photo scales smoothly; pan works when zoomed in; two-finger release maintains zoom level.
**Why human:** `Gesture.Simultaneous(Pinch, Pan)` is correctly coded but gesture interactions require physical touch input.

### 4. Re-scan Button Visibility Gated on Gemini Nano Availability

**Test:** On emulator (emulator-5558), open a meal entry with a photo in edit mode.
**Expected:** "Re-scan with Gemini Nano" button is NOT shown (Gemini Nano unavailable on emulator).
**Why human:** `geminiNanoService.isAvailable()` is device-runtime behavior; emulator returns false by design.

### 5. Drag-and-Drop in Merge View With Undo/Redo

**Test:** If Gemini Nano unavailable: cannot test on emulator. On Pixel 9 Pro: open re-identification merge screen, drag an item from Keep column to Discard. Tap Undo.
**Expected:** Item moves column on drag; Undo returns it to Keep; Redo re-applies move to Discard.
**Why human:** Horizontal drag gesture with midpoint-snap requires physical gesture simulation.
