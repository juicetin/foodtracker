    **1. Create FTP native module** following gemini-nano module pattern:

    **expo-module.config.json:** platforms=["android", "ios"], android module path "expo.modules.ftpclient.FtpClientModule"

    **package.json:** name="ftp-client", main="src/ftpClientModule", peerDeps expo

    **android/build.gradle:** Apply com.android.library and kotlin-android plugins. Add dependency: `implementation("commons-net:commons-net:3.11.1")` for Apache Commons Net FTPClient. Set namespace "expo.modules.ftpclient".

    **AndroidManifest.xml:** Add INTERNET permission (should already be in main app manifest but belt-and-suspenders).

    **FtpClientModule.kt:** Expo module with three async functions:
    - `upload(host: String, port: Int, user: String, pass: String, remotePath: String, localPath: String)` -- connect in passive mode, binary type, storeFile, disconnect
    - `download(host: String, port: Int, user: String, pass: String, remotePath: String, localPath: String)` -- connect in passive mode, retrieveFile to FileOutputStream, disconnect
    - `testConnection(host: String, port: Int, user: String, pass: String)` -- connect, login, list root, disconnect; returns boolean success
    CRITICAL: Always use `client.enterLocalPassiveMode()` (NAT traversal). Always use `FTP.BINARY_FILE_TYPE`. Wrap in try/finally for disconnect. Run on Dispatchers.IO.

    **ios/FtpClientModule.swift:** Stub that throws "FTP not available on iOS yet" for all three functions. iOS deferred per user decision.

    **src/ftpClientModule.ts:** `requireNativeModule('FtpClient')` with typed wrapper:
    ```typescript
    export const ftpClientModule = {
      upload(host, port, user, pass, remotePath, localPath): Promise<void>,
      download(host, port, user, pass, remotePath, localPath): Promise<void>,
      testConnection(host, port, user, pass): Promise<boolean>,
    }
    ```

    **2. Create ftpClient.ts** -- high-level FTP operations with secure credential storage:
    - `FtpCredentials` interface: { host: string, port: number, username: string, password: string, remotePath: string }
    - `saveFtpCredentials(creds)` -- store JSON in expo-secure-store key 'ftp_credentials'
    - `loadFtpCredentials()` -- load from secure store, return null if missing
    - `clearFtpCredentials()` -- delete from secure store
    - `uploadToFtp(localPath, remoteFilename)` -- load creds, call ftpClientModule.upload with remotePath + '/' + remoteFilename
    - `testFtpConnection()` -- load creds, call ftpClientModule.testConnection, return boolean

    Install expo-secure-store: `npx expo install expo-secure-store`

    **3. Create ftpSync.ts** -- mirrors driveSync.ts pattern:
    - `syncToFtp(backupResult: { filename: string })` -- reads backup from local backups dir, uploads via uploadToFtp
    - Uses same BACKUP_DIR = '/backups/' constant as syncScheduler.ts

    **4. Extend types.ts** -- add FtpCredentials type export (or re-export from ftpClient if preferred). Add `| 'ftp-error'` to SyncStatus if needed for independent FTP error tracking (or keep simple with existing SyncStatus).

    **5. Create tests:**
    - `ftpClient.test.ts`: Mock expo-secure-store and ftp-client native module. Test saveFtpCredentials stores JSON, loadFtpCredentials parses JSON, clearFtpCredentials deletes, uploadToFtp calls native upload with correct args, testFtpConnection returns boolean.
    - `ftpSync.test.ts`: Mock ftpClient.uploadToFtp. Test syncToFtp constructs correct local path and calls uploadToFtp.
