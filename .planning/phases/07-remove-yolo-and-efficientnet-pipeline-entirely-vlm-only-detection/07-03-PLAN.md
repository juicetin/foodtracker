    Rewrite the DetectionScreen to reflect the new architecture:

    **Import changes:**
    - Import `runBboxDetection` instead of `runDetectionPipeline` from inferenceRouter
    - Import `DETECT_CLASS_NAMES, DETECT_INPUT_SIZE` only (remove CLASSIFY_INPUT_SIZE)
    - Import `runVlmIdentification, assignDishesToBoxes` from vlmPipeline (remove `runVlmRefinement`)
    - Remove RefiningBadge import, no need for ShimmerPlaceholder import here (it is used internally by BoundingBoxOverlay and DetectionListItem)

    **Inference pipeline rewrite (runInference callback):**
    - Remove `classifyPixels` preprocessing entirely. Only preprocess once at DETECT_INPUT_SIZE (640):
      ```
      const detectPixels = await preprocessImageForModel(uri, DETECT_INPUT_SIZE);
      ```
    - Call `runBboxDetection(detectPixels, DETECT_INPUT_SIZE, DETECT_INPUT_SIZE, DETECT_CLASS_NAMES)` (4 params, no classifyBuffer)
    - Portion estimation: use 'Food Region' as className for initial estimate (generic density fallback). When VLM label arrives, portion will be re-estimated with the real food name.

    **VLM identification flow (replaces VLM refinement useEffect):**
    - After YOLO results arrive and flow enters 'results', start VLM identification:
      1. setRefining(true) -- all items show shimmer
      2. Call `runVlmIdentification(photoUri, items, userMealText || undefined)`
      3. On success: for each item with vlmLabel, call `refineItem(id, { vlmLabel, vlmCuisine, vlmIngredients, vlmConfidence })`
      4. On failure (empty dishes from identifyWithRetry): trigger VLM fallback mode
    - VLM failure handling is now graceful: `runVlmIdentification` internally retries once. If it returns items with no vlmLabels, the fallback UI activates.

    **VLM failure fallback state:**
    - Add local state: `const [vlmFailed, setVlmFailed] = useState(false);`
    - When VLM identification returns and no items have vlmLabel:
      - `setVlmFailed(true)`
      - `setRefining(false)` -- stop shimmer
      - Show the MealTextInput prominently with a helper message: "AI identification unavailable. Describe your meal to get nutrition info."
    - When user submits text (presses done / 500ms debounce):
      - Split text by commas or newlines into dish name array
      - Call `assignDishesToBoxes(items, dishNames)` to map dishes to boxes by area
      - For each assignment, call `refineItem(id, { vlmLabel: dishName })`
      - Call KG `searchDish` for each dish name to surface ingredient info in __DEV__ logs
      - Set `setVlmFailed(false)` after processing

    **Results header changes:**
    - Remove `<RefiningBadge visible={isRefining} />` from the header
    - The shimmer is now INSIDE the bounding boxes and list items (handled by BoundingBoxOverlay and DetectionListItem), not in the header

    **Debounced re-identification on user text change:**
    - Keep the 500ms debounce pattern from Phase 2.6
    - Call `runVlmIdentification` (not `runVlmRefinement`) on text change
    - If vlmFailed is true, user text changes go through assignDishesToBoxes instead of VLM

    **Remove dead code:**
    - Remove `CLASSIFY_INPUT_SIZE` import
    - Remove `classifyPixels` preprocessing (no dual-buffer)
    - Remove `RefiningBadge` import and usage
    - Comment referencing "EfficientNet-Lite0 classification" should be updated or removed

    - Photo selection (camera/gallery) callbacks
    - KG nutrition computation useEffect
    - Log Meal flow
    - Item action handlers (select, remove, undo, portion, correct)
