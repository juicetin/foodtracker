<objective>
Wire the GGCD 241-class detection labels into the inference pipeline, remove COCO food-class filtering, and update DetectionScreen and tests to use the new food-specific detection model.

Purpose: With all 241 YOLO classes being food, the COCO_FOOD_CLASS_IDS filtering step is no longer needed. The pipeline now decodes YOLO output directly into 241 food-specific class labels, and each detection carries a meaningful food name from YOLO (e.g., "rice", "curry", "naan") in addition to the classifier label. This enables proper multi-dish separation -- a photo of rice + curry + naan produces three separate bounding boxes with correct per-box labels.

Output: Updated pipeline code, DetectionScreen wiring, passing tests.

2. Remove the `COCO_FOOD_CLASS_IDS` filtering step entirely. After Phase 2.2, the pipeline has:

   - Stage 2 (classify): Run classifier on whole image, apply label to all detections

3. The `classNames` parameter in `runDetectionPipeline` is now the 241 GGCD food names (passed from DetectionScreen). Update the stride calculation: `const stride = 4 + classNames.length;` (this already works generically -- just verify it handles 241 correctly since `4 + 241 = 245`).

4. Remove the food-class filter line:
   ```typescript
   // REMOVE this:
   const foodDetections = rawDetections.filter((det) => COCO_FOOD_CLASS_IDS.has(det.classId));
   // REPLACE with: use rawDetections directly (all 241 classes are food)
   const foodDetections = rawDetections;
   ```

5. Update detected item construction. Currently all items share the single classify label. With food-specific YOLO, each detection already has a meaningful class name from the 241 GGCD labels. Use the YOLO class name as the primary `className`, and the classifier label as supplementary info. Specifically:
   - Each `DetectedItem.className` should use the YOLO detection class name (from `det.className`), formatted with title-case.
   - The classifier label (from EfficientNet-Lite0 335-class) provides a second opinion but does NOT override the per-box YOLO label.
   - Rename `formatFood101Label` (or its Phase 2.2 equivalent `formatClassLabel`) to `formatFoodLabel` -- it should handle both hyphens and underscores: split on both `-` and `_`, title-case each word, join with spaces.
     Example: `"airan-katyk"` -> `"Airan Katyk"`, `"vegetable based cooked food"` -> `"Vegetable Based Cooked Food"` (already has spaces), `"pad_thai"` -> `"Pad Thai"`.
     Implementation: `rawLabel.split(/[-_\s]+/).map(w => w.charAt(0).toUpperCase() + w.slice(1)).join(' ')`.

6. Simplify the classify stage. Since YOLO now provides meaningful per-box food labels, the classifier serves as confirmation/refinement rather than the primary label source. Keep running it (it provides a broader food taxonomy), but set `DetectedItem.className` to the formatted YOLO label. The classifier result can be stored as an optional secondary field or logged for debugging only. If the Phase 2.2 pipeline already applies classifier label to all items uniformly, update to use per-item YOLO labels instead.
