**Create `training/export_ggcd_detect.py`** -- a focused export script for the GGCD YOLOv8n detection model.

This is a single-purpose script (not modifying the existing `export_mobile.py` which handles the 3-stage pipeline). The script:

1. Loads the GGCD YOLOv8n PyTorch weights from `/home/me/media/foodtracker-ml/models/ggcd-yolo/yolov8n_ggcd.pt` using ultralytics YOLO.
2. Exports to TFLite with **INT8 quantization** per user decision (CONTEXT.md: "INT8 quantization target for mobile"):
   - Primary path: Export to ONNX first (`model.export(format="onnx", imgsz=640, nms=False)`), then use `onnx2tf` with INT8 post-training quantization. Use a representative dataset of ~100 food images from GGCD training data (or generate random calibration data if training images unavailable) for INT8 calibration.
   - Alternative INT8 path: `ultralytics` direct export with `format="tflite"`, `int8=True`, `imgsz=640`, `nms=False`. This requires a calibration dataset; set `data="coco128.yaml"` or a custom GGCD calibration YAML as the representative dataset.
   - Fallback ONLY if INT8 fails: Export FP16 (`half=True`) and log a warning: "INT8 export failed, falling back to FP16. Re-attempt INT8 with Docker onnx2tf container if needed."
   - Per existing convention: `nms=False` (NMS done in JavaScript).
   - If ultralytics export fails (some YOLOv8 versions have issues), fall back to ONNX -> onnx2tf pipeline.
3. Validates the exported TFLite:
   - Load with ai-edge-litert (or tflite_runtime as fallback).
   - Verify input shape is `[1, 640, 640, 3]` (NHWC) and dtype is float32 (INT8 models typically still accept float32 input with built-in quantize/dequantize ops) or uint8.
   - Verify output shape contains `245` (4 bbox + 241 classes) in one dimension.
   - Log input/output details and quantization type (INT8 vs FP16).
4. Copies the validated TFLite to `apps/mobile/assets/models/detect.tflite` (overwriting the YOLO11n COCO model).
5. Creates `apps/mobile/assets/models/labels_detect.json` from the GGCD classes file:
   ```json
   {
     "source": "GGCD/YOLOv8n",
     "count": 241,
     "classNames": ["achichuk", "airan-katyk", ..., "zucchini"]
   }
   ```
   Copy directly from `/home/me/media/foodtracker-ml/models/ggcd-yolo/ggcd_classes.json`.

Script should accept `--weights`, `--output-dir`, `--validate`, `--quantization` arguments similar to `export_mobile.py`.
Default `--weights` to `/home/me/media/foodtracker-ml/models/ggcd-yolo/yolov8n_ggcd.pt`.
Default `--output-dir` to `apps/mobile/assets/models/`.
Default `--quantization` to `int8` (with `fp16` as accepted alternative).

**Run the export script** after creating it:

```bash
cd /home/me/repos/personal/foodtracker && python training/export_ggcd_detect.py --validate --quantization int8
```

If the export fails due to Python/TF version issues (CONTEXT mentions Docker may be needed for onnx2tf), try these fallbacks in order:
1. `ultralytics` direct export with `int8=True` (preferred)
2. Export to ONNX first (`model.export(format="onnx", imgsz=640)`), then use `onnx2tf` CLI with INT8 quantization
3. If INT8 fails entirely, fall back to FP16 and log clearly: "Using FP16 per INT8 failure -- revisit with Docker onnx2tf"
4. If all else fails, use the existing `export_mobile.py` with `--detect-weights /home/me/media/foodtracker-ml/models/ggcd-yolo/yolov8n_ggcd.pt`
