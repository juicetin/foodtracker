  <action>
**Build the APK:**

1. Run the EAS local build (eas.json already exists from Phase 2.1 Plan 03):
   ```bash
   cd apps/mobile && npx eas build --platform android --profile preview --local
   ```
   If `--local` fails, fall back to cloud build:
   ```bash
   cd apps/mobile && npx eas build --platform android --profile preview
   ```

2. Copy and rename the output APK to `foodtracker-release.apk` per project naming convention. Copy to `/tmp/claude-shared-files/foodtracker-release.apk` for device access. Also copy to `/home/me/media/foodtracker/builds/` for archival.

3. Verify APK size is reasonable (expected ~30-50MB base + ~10-20MB models depending on INT8 vs FP16).

**Emulator smoke-test:**

Use the project's dedicated emulator: port 5558, serial `emulator-5558`, AVD `Pixel_9_FoodTracker`.

4. Check if the emulator is already running:
   ```bash
   adb devices | grep emulator-5558
   ```
   If not running, start it:
   ```bash
   emulator -avd Pixel_9_FoodTracker -no-audio -no-window -no-snapshot -port 5558 -read-only &
   ```
   If the AVD does not exist, create it first:
   ```bash
   avdmanager create avd -n Pixel_9_FoodTracker -k "system-images;android-35;google_apis;x86_64" -d pixel_9 --force
   ```
   Wait for the emulator to boot (`adb -s emulator-5558 wait-for-device && adb -s emulator-5558 shell getprop sys.boot_completed` returns `1`).

5. Install the APK:
   ```bash
   adb -s emulator-5558 install -r /tmp/claude-shared-files/foodtracker-release.apk
   ```

6. Push test images to the emulator for detection testing. Use multi-food test images that contain 2-3 dishes (e.g., rice + curry, pizza + salad). Check `/home/me/repos/personal/foodtracker/testassets/` for existing test images, or download sample multi-food images to the emulator's gallery:
   ```bash
   adb -s emulator-5558 push testassets/*.jpg /sdcard/DCIM/Camera/
   ```
   If no test images exist in testassets, create a simple test by taking a screenshot or using stock food images.

7. Launch the app and navigate to detection:
   ```bash
   adb -s emulator-5558 shell am start -n com.jtingexpo.mobile/.MainActivity
   ```

8. Use `adb shell` commands to verify the app launched without crash:
   ```bash
   adb -s emulator-5558 shell pidof com.jtingexpo.mobile
   ```
   If the process is not running, check logcat for crash:
   ```bash
   adb -s emulator-5558 logcat -d -t 50 --pid=$(adb -s emulator-5558 shell pidof com.jtingexpo.mobile) 2>/dev/null || adb -s emulator-5558 logcat -d -t 100 | grep -i 'fatal\|crash\|error.*tflite\|error.*model'
   ```

9. Take a screenshot to verify the app is running:
   ```bash
   adb -s emulator-5558 shell screencap -p /sdcard/screenshot.png && adb -s emulator-5558 pull /sdcard/screenshot.png /tmp/claude-shared-files/foodtracker-emulator-test.png
   ```

<task type="checkpoint:human-verify" gate="blocking">
  <name>Task 2: Verify multi-dish detection on emulator</name>
  <files></files>
  <action>Human verifies the full detection pipeline on the emulator or a physical device using the built APK. Tests single-food detection with GGCD labels, multi-dish separation, and pipeline stability.</action>
  <what-built>
Full detection pipeline with GGCD YOLOv8n (241 food-specific classes) replacing COCO YOLO11n (10 food classes). The APK now detects food items using food-specific class labels and should separate multiple dishes in a single photo into distinct bounding boxes.
  </what-built>
  <how-to-verify>
Install the APK from `http://100.78.19.90:8888/foodtracker-release.apk` (or use the emulator where it is already installed).

**Test 1: Single food detection with GGCD label**
1. Open the app and navigate to detection
2. Select/photograph a single food item (e.g., rice, pizza, salad)
3. Verify: bounding box appears with a food-specific GGCD class name (e.g., "Rice", "Pizza", "Salad") -- NOT a generic COCO class
4. Verify: confidence indicator shows green/yellow/red

**Test 2: Multi-dish separation**
1. Select a photo containing 2-3 different food items (e.g., rice + curry on a plate, or a tray with multiple dishes)
2. Verify: separate bounding boxes appear for each distinct food item
3. Verify: each box has its own food-specific label (e.g., "Rice" and "Curry", not both labeled the same)

**Test 3: Pipeline stability**
1. Run detection on 3-4 different food photos
2. Verify: no crashes, no freezes, results appear within ~3 seconds
3. Verify: the full flow works (detect -> review -> log meal)

**Expected behavior:**
- 241 food classes are available (Central Asian, South Asian, East Asian, Middle Eastern, European, American cuisines)
- Labels are title-cased (e.g., "Pad Thai", "Airan Katyk", "Vegetable Soup")
- Non-food items should NOT be detected (the model only knows food)
