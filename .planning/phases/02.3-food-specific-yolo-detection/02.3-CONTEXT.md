**Gathered:** 2026-03-13
**Status:** Ready for planning
**Source:** Discussion during GGCD dataset research

<domain>
## Phase Boundary

Replace COCO YOLO11n (80 classes, only 10 are food) with GGCD YOLOv8n (241 food-specific classes, 6.7MB) in the detection pipeline. Convert the PyTorch model to TFLite, update post-processing for YOLOv8 output format, and verify multi-dish detection on-device.

</domain>

<decisions>
## Implementation Decisions

### Model Source
- GGCD YOLOv8n PyTorch weights: `/home/me/media/foodtracker-ml/models/ggcd-yolo/yolov8n_ggcd.pt` (6.7MB)
- 241 food class names: `/home/me/media/foodtracker-ml/models/ggcd-yolo/ggcd_classes.json`
- Source dataset: Global Gastronomic Culinary Dataset (HuggingFace issai/Global_Gastronomic_Culinary_Dataset)

### TFLite Conversion
- Export YOLOv8n → ONNX → TFLite (same pipeline used for EfficientNet-Lite0 export)
- INT8 quantization target for mobile
- Input size: likely 640x640 (standard YOLOv8) — verify during conversion
- May need Docker container for onnx2tf (Python 3.14 incompatibility with TensorFlow)

### Pipeline Changes
- Replace YOLO11n COCO detection model with GGCD YOLOv8n
- Update class labels from COCO 80-class to GGCD 241-class food names
- Remove food-class filtering (COCO_FOOD_CLASS_IDS) — all 241 classes ARE food
- Post-processing may differ: verify YOLOv8 output tensor shape vs YOLO11n
- NMS parameters may need tuning for food-specific detection

### Code Impact
- `apps/mobile/src/services/detection/constants.ts` — replace COCO class names with GGCD food classes
- `apps/mobile/src/services/detection/inferenceRouter.ts` — remove food-class filter, update output parsing
- `apps/mobile/assets/models/` — swap detection model
- `apps/mobile/assets/models/model_manifest.json` — update detection model entry

### Claude's Discretion
- YOLOv8 vs YOLO11 output format differences and how to handle them
- NMS threshold tuning for food detection (may need different IoU threshold than general COCO)
- Whether to keep COCO YOLO as a fallback

</decisions>

<specifics>
## Specific Details

- Current YOLO11n output shape: [1, 84, 8400] — 80 classes + 4 bbox coords
- YOLOv8n output: likely [1, 245, 8400] — 241 classes + 4 bbox coords (verify)
- GGCD covers cuisines from: Central Asian, South Asian, East Asian, Middle Eastern, European, American
- The 241 classes include specific dishes (not just food categories), which is ideal for our pipeline
- Multi-food detection is the primary UX improvement: two dishes on one plate → two separate bounding boxes

</specifics>

<deferred>
## Deferred Ideas

- Fine-tuning GGCD YOLO on additional food photos for better accuracy
- Using food-specific YOLO classes to improve classifier routing
- Instance segmentation (separate overlapping dishes)

</deferred>
