# Phase 3.7: Google Drive Sync - Context

**Gathered:** 2026-03-20
**Status:** Ready for planning

<domain>
## Phase Boundary

Enable users to sync incremental backups to Google Drive for cross-device restore and cloud safety. This builds on Phase 3.6's incremental backup system.

</domain>

<decisions>
## Implementation Decisions

### OAuth Scope
- `drive.appdata` by default (narrow, hidden app-specific folder on user's Drive)
- User can pick a custom Drive folder in settings (upgrades to `drive.file` scope at that point)

### Sync Trigger
- WiFi only by default
- User-configurable override to allow backup on any connection

### Conflict Resolution
- Per-field last-write-wins (LWW) by default
- Prompts user to resolve each conflict individually
- Settings toggle for auto-resolve (silent per-field LWW) for power users

### Backup Strategy
- Incremental diffs that periodically vacuum/compact into merged full backup
- No redundant full backups each time
- Retention policy is implementation detail (Claude's discretion)

### Claude's Discretion
- Specific library choice (react-native-cloud-storage, @react-native-google-signin, expo-auth-session, etc.)
- Backup file format (JSON, SQLite dump, custom binary)
- Compaction frequency (every N incrementals, or time-based)
- Conflict resolution UI design (list view, diff view, or simple accept/reject)
- Background sync implementation (WorkManager on Android)
- Retry/error handling strategy for failed uploads

</decisions>

<code_context>
## Existing Code Insights

### Reusable Assets
- **Phase 3.6 incremental backup system** — already built, produces incremental diffs and full snapshots
- **backup/types.ts** — backup data types, TRACKED_TABLES list
- **usePreferencesStore** — can store sync preferences (WiFi-only, auto-resolve)
- **ProfileScreen** — has Preferences section for adding sync settings

### Established Patterns
- Zustand stores with AsyncStorage persistence
- op-sqlite for database operations
- Plain StyleSheet UI

### Integration Points
- Phase 3.6 backup output → Google Drive upload
- Google Drive download → Phase 3.6 restore flow
- ProfileScreen → sync settings + manual backup button
- App background event → trigger auto-upload

</code_context>

<specifics>
## Specific Ideas

- The existing backup system from Phase 3.6 should be the foundation — this phase adds the cloud transport layer
- Conflict resolution UI should be simple and clear — most users will never see it (single-device usage)
- The "discover and restore" flow for fresh installs is critical for the user experience

</specifics>

<deferred>
## Deferred Ideas

- iCloud sync (deferred until iOS release, which is deferred until Apple has comparable on-device AI)
- FTP server backup option (Phase 6)
- Multi-device simultaneous sync (complex — defer edge cases to post-v1.0)

</deferred>
