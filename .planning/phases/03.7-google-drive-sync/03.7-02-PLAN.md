  <action>
    **syncScheduler.ts** - Extends existing backup with Drive upload:
    - `triggerManualSync()`: async function that:
      1. Checks isSignedIn() -- returns early if not
      2. Checks WiFi gate via NetInfo.fetch() against useSyncStore.wifiOnly
      3. Sets syncStatus to 'syncing'
      4. Calls performIncrementalBackup() to create local backup
      5. If backup produced, calls uploadIncremental() with the backup filename and local path
      6. Downloads current sync manifest, appends new incremental ID, uploads updated manifest
      7. Sets lastSyncAt and syncStatus to 'idle' in useSyncStore
      8. On error: sets syncStatus to 'error', logs in __DEV__
    - `registerSyncTask()`: modifies the existing BACKUP_TASK_NAME task callback to also call triggerManualSync() after local backup. This is done by updating backupScheduler.ts to import and call syncScheduler after local backup completes.

    **Modify backupScheduler.ts** to add Drive sync after local backup:
    - After successful performIncrementalBackup + compactBackups in the task callback, dynamically import syncScheduler and call triggerManualSync()
    - Wrap in try/catch so Drive sync failure does not fail the local backup task

    **restoreService.ts** - Restore flow for fresh install:
    - `discoverRemoteBackups()`: calls downloadSyncManifest(), if exists parses and returns the manifest's backup entries (full + incrementals). Returns null if no manifest found.
    - `restoreFromDrive()`:
      1. Downloads the sync manifest
      2. Finds the latest full backup entry
      3. Downloads full .db file to local backup directory
      4. Downloads each incremental after the full backup in chronological order
      5. Replaces the live database with the full backup (close current DB, copy downloaded .db over it, reopen)
      6. Replays each incremental changeset using the same logic as compactBackups() in backupService.ts
      7. Returns success/failure
    - NOTE: Database replacement requires closing op-sqlite, copying file, reopening. Reference the existing `open()` pattern from db/client.ts.
  </action>
