### Human Verification Required

All four items are unchanged from initial verification — these require real GCP credentials and physical device testing. No automated proxy exists for these flows.

#### 1. Google OAuth Sign-In Flow

**Test:** Build APK, install on device with Play Services, open Profile tab, tap sync card, tap "Sign in with Google"
**Expected:** Google account picker appears, selecting an account completes OAuth, user email shown in Google Account card
**Why human:** Requires Google Cloud Console project with Android + Web OAuth Client IDs configured. webClientId in driveAuth.ts is a runtime placeholder pending GCP setup.

#### 2. Sync Now Uploads to Drive

**Test:** After signing in, log a food entry, tap "Sync Now" in SyncSettingsScreen
**Expected:** ActivityIndicator shows briefly, "Sync Complete" alert appears, last sync time updates to current time on both SyncSettingsScreen and ProfileScreen SyncCard
**Why human:** End-to-end Drive API call requires live OAuth token and real Drive API.

#### 3. WiFi-Only Gate Behavior

**Test:** Enable WiFi-only toggle, switch device to cellular, tap "Sync Now"
**Expected:** Silent early return (no error, no upload). Disable WiFi-only, tap "Sync Now" on cellular — sync proceeds.
**Why human:** Requires physical device with cellular and WiFi connection switching.

#### 4. Restore Flow on Fresh Install

**Test:** After syncing, uninstall app, reinstall, sign in, tap "Restore from Drive"
**Expected:** Alert shows backup date from manifest, confirming restore downloads full DB + incrementals, shows "app restart required" alert. After restart, data is present.
**Why human:** Requires multi-step reinstall scenario; DB file copy and app restart behavior cannot be verified programmatically.
