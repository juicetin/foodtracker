Create `apps/mobile/src/services/backup/backupService.ts` as a plain TS module (named exports, not a class) following the exportService.ts pattern:

1. **Imports:**
   - `opsqlite` from `../../../db/client`
   - `open` from `@op-engineering/op-sqlite`
   - `* as FileSystem` from `expo-file-system`
   - `getJournalEntries`, `clearJournal`, `getJournalCount` from `./changeJournal`
   - Types from `./types` (TRACKED_TABLES, BACKUP_DIR, ChangeJournalEntry, IncrementalChangeset, BackupMetadata)

2. **Helper: `ensureBackupDir()`**
   - `const dir = FileSystem.documentDirectory + BACKUP_DIR`
   - `await FileSystem.makeDirectoryAsync(dir, { intermediates: true }).catch(() => {})`
   - Returns `dir`

3. **`performIncrementalBackup(): Promise<{ filename: string; changeCount: number } | null>`**
   - Read all journal entries via `getJournalEntries()`
   - If empty, return null (nothing to back up)
   - Build `IncrementalChangeset` object:
     - `backupId`: `crypto.randomUUID()`
     - `createdAt`: `new Date().toISOString()`
     - `sinceLastBackup`: query `_backup_metadata` for latest backup's `created_at`, or null
     - `tableChangeCounts`: group entries by table_name, count insert/update/delete per table
     - `changes`: the journal entries array
   - Generate filename: `tastimate-backup-incremental-${new Date().toISOString().replace(/[:.]/g, '-')}.json`
   - Write JSON to `backupDir + filename` via `FileSystem.writeAsStringAsync`
   - Get file info for size: `FileSystem.getInfoAsync(filePath)`
   - Record in `_backup_metadata`: INSERT with id=backupId, type='incremental', filename, journal_from=first entry timestamp, journal_to=last entry timestamp, size_bytes, parent_full_id=latest full backup id or null
   - Clear journal via `clearJournal(lastEntryTimestamp)`
   - Return `{ filename, changeCount: entries.length }`

4. **`performFullBackup(): Promise<{ filename: string; sizeBytes: number }>`**
   - Generate filename: `tastimate-backup-full-${new Date().toISOString().replace(/[:.]/g, '-')}.db`
   - Full path = `backupDir + filename`
   - Delete target file first if exists (VACUUM INTO requires non-existent target): `FileSystem.deleteAsync(fullPath, { idempotent: true })`
   - Execute: `await opsqlite.execute('VACUUM INTO ?', [fullPath])`
   - Get file info for size
   - Record in `_backup_metadata`: INSERT with id=crypto.randomUUID(), type='full', filename, size_bytes
   - Clear entire journal via `clearJournal()`
   - Return `{ filename, sizeBytes }`

5. **`compactBackups(): Promise<{ filename: string } | null>`**
   Compaction replays incremental JSON diffs onto the last full backup to produce a merged full backup (per user decision -- do NOT shortcut with VACUUM INTO).

   Steps:
   - Query `_backup_metadata` for latest full backup (type='full' ORDER BY created_at DESC LIMIT 1). If none exists, return null.
   - Query all incrementals with `created_at > latestFull.created_at` ordered by `created_at ASC`.
   - If fewer than 7 incrementals, return null (not enough to compact).
   - **Copy the last full backup file to a new file:**
     - New filename: `tastimate-backup-full-${new Date().toISOString().replace(/[:.]/g, '-')}.db`
     - `await FileSystem.copyAsync({ from: backupDir + latestFull.filename, to: backupDir + newFilename })`
   - **Open the copy with op-sqlite** (separate connection, NOT the live DB):
     - `const backupDb = open({ name: newFilename, location: backupDir })`
   - **For each incremental JSON file (sorted by created_at ASC):**
     - Read the JSON file: `const json = await FileSystem.readAsStringAsync(backupDir + inc.filename)`
     - Parse as `IncrementalChangeset`
     - For each change entry in `changeset.changes`:
       - If operation is `'DELETE'`: execute on backupDb: `DELETE FROM ${change.table_name} WHERE rowid = ?` with `[change.row_id]`
       - If operation is `'INSERT'` or `'UPDATE'`: query the **live** DB (`opsqlite`) for current row state: `SELECT * FROM ${change.table_name} WHERE rowid = ?` with `[change.row_id]`. If the row exists in live DB, build an `INSERT OR REPLACE INTO ${change.table_name} (col1, col2, ...) VALUES (?, ?, ...)` using the column names from the result keys and values from the row, and execute on `backupDb`. If the row no longer exists in live DB (was deleted after this incremental), skip it.
   - **VACUUM the copy** to clean up: `backupDb.executeSync('VACUUM')`
   - **Close the backup connection:** `backupDb.close()`
   - Get file info for size of the new backup file
   - Record in `_backup_metadata`: INSERT with new id, type='full', filename=newFilename, size_bytes
   - Delete superseded incrementals: for each incremental processed, delete its file from disk via `FileSystem.deleteAsync`, then DELETE FROM `_backup_metadata` WHERE id = inc.id
   - Call `cleanupOldBackups()` for retention
   - Return `{ filename: newFilename }`

   **Important:** Table names in the journal are from TRACKED_TABLES (a known safe set), so string interpolation into SQL is safe here. The column names come from SELECT result keys which are also DB-originated. Do NOT accept arbitrary user input for table/column names.

6. **`cleanupOldBackups(): Promise<void>`**
   - Query all full backups ordered by created_at DESC
   - Keep first 3, delete the rest from both disk and _backup_metadata
   - For each deleted full backup, also delete its associated incrementals (by parent_full_id or by created_at range)

7. **`listBackups(): BackupMetadata[]`**
   - SELECT * FROM _backup_metadata ORDER BY created_at DESC
   - Try-catch returns []
   - Cast rows to BackupMetadata[]
