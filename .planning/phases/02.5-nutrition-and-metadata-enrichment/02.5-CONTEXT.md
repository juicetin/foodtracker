# Phase 2.5: Nutrition & Metadata Enrichment - Context

**Gathered:** 2026-03-13
**Status:** Ready for planning
**Source:** HuggingFace research survey + nutrition data analysis

<domain>
## Phase Boundary

Enrich the app's nutrition database and food metadata layer with three sources: Open Food Facts (packaged food nutrition), Nutrition5k (per-dish calorie ground truth), and WorldCuisines (multilingual labels + cuisine tags). Ensure every classified food returns nutrition data and cultural context.

</domain>

<decisions>
## Implementation Decisions

### Open Food Facts Integration
- Dataset: `openfoodfacts/product-database` — 4.4M products, 150+ countries
- Use case: Nutrition lookup for packaged/branded foods, barcode scanning data
- Strategy: Filter to food products with complete nutrition data, import into nutrition DB
- Format: Parquet (4.44M rows), AGPL-3.0 / ODbL license
- NOT for image classification — for nutrition data lookup only

### Nutrition5k Integration
- Dataset: `mmathys/food-nutrients` — 3,260 cafeteria plates, CC license
- Use case: Ground-truth per-dish calorie/macro data (total calories, fat, carbs, protein per plate + per ingredient)
- Strategy: Map dish names to our classifier classes, use as reference nutrition values
- Supplements the existing 200 curated Asian dishes + USDA data

### WorldCuisines Integration
- Dataset: `worldcuisines/food-kb` — 2,414 dishes, 35+ countries, 30+ languages
- Use case: Multilingual food labels, cuisine tags, country associations
- Strategy: Map our 700+ class names to WorldCuisines entries, extract translations and cuisine metadata
- Display cuisine context in detection results (e.g., "pad thai" → "Thai cuisine")

### Existing Nutrition Infrastructure
- Phase 1 built: op-sqlite nutrition DB, USDA FDC data, regional DB resolver, pack manager
- Phase 1 built: Asian foods nutrition data (200 curated dishes)
- Open Food Facts filtering already started (474MB+ downloaded)
- Nutrition DB at: apps/mobile/src/services/nutrition/

### Claude's Discretion
- How to handle conflicts between nutrition sources (USDA vs OFF vs Nutrition5k)
- Storage format for WorldCuisines metadata (separate DB table vs JSON asset)
- Whether to ship OFF data as a downloadable pack or bundle a subset
- Barcode scanning UI (may be deferred to v2 per UI-10)

</decisions>

<specifics>
## Specific Details

- Current nutrition coverage: USDA FDC (generic US foods) + 200 curated Asian dishes
- Gap: Many of the 700+ classifier classes will have no nutrition mapping
- Open Food Facts download: `/home/me/media/foodtracker-ml/` area
- Build scripts: `apps/data-pipeline/` (existing USDA build pipeline)
- Regional DB resolver: `apps/mobile/src/services/nutrition/regionalResolver.ts`
- The goal is that EVERY food the classifier can identify has at least a rough nutrition estimate

</specifics>
