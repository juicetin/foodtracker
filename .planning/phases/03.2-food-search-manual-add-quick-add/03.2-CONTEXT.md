# Phase 3.2: Food Search + Manual Add + Quick Add - Context

**Gathered:** 2026-03-20
**Status:** Ready for planning

<domain>
## Phase Boundary

Enable users to add food without the camera — via text search (KG + OFF), personal history, or raw macro entry. This is the primary non-camera food logging path.

</domain>

<decisions>
## Implementation Decisions

### Search Ranking & Results
- History ranking uses a blend: show top results by BOTH frequency (most logged) and recency (most recent), depending on screen real estate
- Search results stream as user types with debounce (not batch on Enter)
- KG dishes + OFF cache queried simultaneously

### Quick Add Validation
- Mathematically validate macro entry: `(protein*4 + fat*9 + carbs*4) ≈ calories` within small rounding tolerance (nearest whole number)
- Clear visual indicator when maths doesn't match (e.g. red border or warning text)
- Allow submission even with mismatch — just flag it visually

### Barcode Stub
- No-op for now — icon present but no action. Will be built before release (not a stub screen or toast)

### Claude's Discretion
- Search bar exact placement and styling on diary view
- Debounce delay for streaming search (200-300ms typical)
- How to display blended frequency/recency results (separate sections vs interleaved)
- Quick Add form layout and field order
- Serving size selection UI for search results

</decisions>

<specifics>
## Specific Ideas

- The "under 5 taps" requirement means: search → select → confirm serving → logged. No unnecessary confirmation screens.
- "From History" should feel like a smart default — the foods the user eats regularly should be front and center.
- Quick Add is the escape hatch for when everything else fails — it should be frictionless.

</specifics>
