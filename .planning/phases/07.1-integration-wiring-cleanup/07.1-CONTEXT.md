# Phase 7.1: Integration Wiring + Dead Code Cleanup - Context

**Gathered:** 2026-03-21
**Status:** Ready for planning

<domain>
## Phase Boundary

Fix 2 broken E2E flows (gallery→diary, scale→portion), remove orphaned code from the YOLO→VLM-only pivot, and close remaining audit gaps. This is a gap closure phase — no new features.

</domain>

<decisions>
## Implementation Decisions

### Gallery → Diary Flow
- Auto-queue: automatically run Gemini Nano identification on all grouped meal photos discovered by gallery scan
- User reviews/confirms the batch results (not per-meal approval before identification)
- drainScanQueue pipeline should end with diary entry creation, not just classification counts

### Scale Weight Return
- Replace total entry weight: scale reading becomes the meal's total weight
- Proportionally adjust all ingredient weights based on the new total
- Allow user to adjust the total weight in case it includes container weight (tare)
- ScaleInputScreen returns netWeight via navigation params to caller

### Confidence Display (DET-05)
- DROPPED: Gemini Nano doesn't produce confidence scores like YOLO did
- Remove DET-05 from requirements — the old confidence indicator UI is irrelevant
- No replacement confidence display needed

### Dead Code Removal
- Clean delete ALL orphaned code:
  - VlmDownloadScreen
  - vlmService.ts (SmolVLM via llama.rn)
  - DetectionListItem, PortionSlider, ItemDetailSheet, SummaryBar
  - portionBridge.ts
- No dormant SmolVLM fallback — Gemini Nano only strategy is final
- DET-06 (portionBridge) also dropped — Gemini Nano provides gram estimates directly

### Claude's Discretion
- Exact proportional weight redistribution algorithm
- How to present auto-queued gallery results to user (inline in diary vs separate review screen)
- Which navigation param pattern to use for scale weight return (params vs route callback)

</decisions>
