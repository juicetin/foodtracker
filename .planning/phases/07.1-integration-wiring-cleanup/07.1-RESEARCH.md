## Architecture Patterns

### Pattern 1: Navigation Params for Return Values
**What:** React Navigation does not natively support "return values" from screens. Two patterns exist:
1. **Route params with callback** -- caller passes an `onResult` callback in params, callee invokes it before goBack
2. **Navigation event listener** -- caller listens for focus event and reads params set by callee

**Recommendation: Route params callback.** The ScaleInputScreen JSDoc already documents `onResult` as an optional callback param. The current code simply never invokes it.

**Implementation:**
```typescript
// In RootStackParamList types:
ScaleInput: { photoUri?: string; onResult?: (netWeight: number) => void };

// In ScaleInputScreen handleConfirm:
async function handleConfirm() {
  if (netWeight <= 0) { /* ... */ return; }
  if (selectedContainer) { await recordContainerUsage(selectedContainer.id); }
  route.params?.onResult?.(netWeight);
  if (navigation.canGoBack()) navigation.goBack();
}

// In DetectionScreen when navigating to ScaleInput:
navigation.navigate('ScaleInput', {
  photoUri: photoUri ?? undefined,
  onResult: (netWeight: number) => { /* apply weight to dishes */ },
});
```

**Caveat:** React Navigation serializes params for state persistence. Callbacks are not serializable. This is acceptable because ScaleInput is a modal that is never deep-linked or restored from state -- it is always pushed from DetectionScreen.

### Pattern 2: Proportional Weight Redistribution
**What:** When scale weight replaces total, all ingredient amounts scale proportionally.
**Algorithm:**
```typescript
function applyScaleWeight(dishes: ScannedDish[], scaleNetWeight: number): ScannedDish[] {
  const currentTotal = dishes.reduce((sum, d) =>
    sum + d.ingredients.reduce((s, i) => s + i.amount_g, 0), 0);
  if (currentTotal <= 0) return dishes;
  const ratio = scaleNetWeight / currentTotal;
  return dishes.map(d => ({
    ...d,
    ingredients: d.ingredients.map(i =>
      i.userModified ? i : { ...i, amount_g: Math.round(i.amount_g * ratio * 10) / 10 }
    ),
  }));
}
```
**Key:** Skip user-modified ingredients (respect manual edits). Round to 1 decimal.

## Common Pitfalls

### Pitfall 1: Non-Serializable Navigation Params
**What goes wrong:** React Navigation warns about non-serializable params (functions in route.params).
**Why it happens:** `onResult` callback in ScaleInput params is a function.
**How to avoid:** This warning is acceptable for modal screens that are never deep-linked. Suppress the specific warning or accept it as a known tradeoff. Alternative: use navigation.setParams on the parent screen, but this is more complex.
**Warning signs:** Yellow box warning in dev mode about non-serializable values.

### Pitfall 2: Gallery Pipeline Running Gemini Nano in Background
**What goes wrong:** Gemini Nano requires foreground -- AICore returns BUSY if called from background.
**Why it happens:** Gallery scan can be triggered from background WorkManager.
**How to avoid:** The identify step must only run during foreground drain (AppState 'active'). The background scan should stop at classify+group. The foreground drain already exists via AppState listener.
**Warning signs:** BUSY errors from AICore during background processing.

### Pitfall 3: Stale Imports After File Deletion
**What goes wrong:** TypeScript build fails because barrel exports reference deleted files.
**Why it happens:** Deleting files without updating re-exports.
**How to avoid:** Update ALL barrel index files (screens/index.ts, components/detection/index.ts, services/vlm/index.ts) in the same commit as file deletions.
**Warning signs:** `Module not found` errors.

### Pitfall 4: Scale Weight Applied to Wrong Scope
**What goes wrong:** Scale weight replaces a single ingredient weight instead of total meal weight.
**Why it happens:** Ambiguity about what "total weight" means across multiple dishes.
**How to avoid:** Scale weight represents the total weight of ALL food on the scale. Distribute across ALL ingredients in ALL dishes proportionally.
**Warning signs:** Nutrition totals don't change proportionally to weight change.
