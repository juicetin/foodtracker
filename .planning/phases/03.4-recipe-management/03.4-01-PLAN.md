    - saveEntryAsRecipe('entry-1', 'My Recipe', 2) creates a custom_recipe row with source_entry_id='entry-1', servings=2, copies all dish ingredients, copies first photo as photo_uri, returns recipe ID
    - saveEntryAsRecipe copies ingredient nutrition values (calories, protein, carbs, fat) faithfully from entry ingredients
    - searchRecipes('pasta') returns matching recipes sorted by times_used DESC, limited to requested count
    - searchRecipes('') returns empty array (no wildcard search)
    - updateRecipeWithVersioning(recipeId, newIngredients, 'update-all') updates recipe ingredients and recalculates all linked food_entries via source_recipe_id
    - updateRecipeWithVersioning(recipeId, newIngredients, 'save-as-new') creates a new recipe with modified ingredients, leaves original unchanged
    - logRecipeAsEntry now sets source_recipe_id on the food_entry (not just notes string)
    - logRecipeAsEntry scales ingredient nutrition by servingCount when servingCount != 1
  </behavior>
  <action>
    1. In client.ts, add CREATE TABLE IF NOT EXISTS blocks for custom_recipes (matching Drizzle schema columns + source_entry_id FK), recipe_ingredients (with cascade FK), and recipe_photos (with cascade FK). Add idempotent ALTER TABLE statements:
       - `ALTER TABLE custom_recipes ADD COLUMN servings INTEGER DEFAULT 1` (try/catch)
       - `ALTER TABLE custom_recipes ADD COLUMN photo_uri TEXT` (try/catch)
       - `ALTER TABLE food_entries ADD COLUMN source_recipe_id TEXT` (try/catch)

    2. In backup/types.ts, add 'recipe_ingredients' and 'recipe_photos' to TRACKED_TABLES set.

    3. In recipeService.ts, add `servings` and `photoUri` to RecipeSummary interface. Update mapRecipeRow to include them. Update RecipeInput to accept optional `servings` and `sourceEntryId`.

    4. Add `saveEntryAsRecipe(entryId: string, recipeName: string, servings?: number): string` function:
       - Query scanned_dishes WHERE entry_id = entryId
       - Query ingredients WHERE entry_id = entryId
       - Query photos WHERE entry_id = entryId (first photo's local_path or uri becomes photo_uri)
       - INSERT into custom_recipes with name, source_entry_id=entryId, servings (default 1)
       - INSERT each ingredient into recipe_ingredients
       - INSERT each photo into recipe_photos (first = is_primary)
       - Call recalculateRecipeTotals
       - Return recipe ID

    5. Add `searchRecipes(query: string, limit?: number): RecipeSummary[]`:
       - If query is empty/whitespace, return []
       - SELECT * FROM custom_recipes WHERE name LIKE '%query%' COLLATE NOCASE ORDER BY times_used DESC, last_used_at DESC NULLS LAST LIMIT limit (default 10)

    6. Add `updateRecipeWithVersioning(recipeId: string, ingredients: RecipeIngredientInput[], mode: 'update-all' | 'save-as-new'): string`:
       - If mode === 'save-as-new': create new recipe (copy name + " (edited)"), add all ingredients, return new ID
       - If mode === 'update-all':
         a. Delete all existing recipe_ingredients for recipeId
         b. Insert new ingredients
         c. Recalculate recipe totals
         d. Find all food_entries with source_recipe_id = recipeId WHERE all ingredients have user_modified = 0
         e. For each such entry: delete old ingredients, insert new ingredients (scaled to entry's portion), recalculate entry totals
         f. Return original recipeId

    7. Update `logRecipeAsEntry` to:
       - Accept optional `servingCount` parameter (default 1)
       - Set source_recipe_id on the food_entry INSERT
       - Scale ingredient nutrition by servingCount (calories * servingCount, etc.)
       - Scale entry totals by servingCount

    8. Write tests in recipeService.test.ts for all new functions (extend existing test file). Mock opsqlite calls as per existing pattern.
  </action>
