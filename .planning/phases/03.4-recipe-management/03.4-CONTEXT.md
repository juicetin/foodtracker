# Phase 3.4: Recipe Management - Context

**Gathered:** 2026-03-20
**Status:** Ready for planning

<domain>
## Phase Boundary

Enable users to save logged meals as reusable recipes, build a personal recipe library, and re-log recipes in 1-2 taps. Integrates recipes into the food search flow.

</domain>

<decisions>
## Implementation Decisions

### Recipe Naming
- Gemini Nano auto-suggests a recipe name (update the identification prompt to include recipe name suggestion)
- User can override the suggested name

### Serving Count
- Allow measuring by servings AND/OR weight — both options available

### Recipe Versioning
- On recipe edit, prompt user with two choices:
  - "Update all" — unified recipe, rewrites all historical diary entries that used this recipe
  - "Save as new" — fork to new recipe with different name, old recipe preserved and still editable

### Claude's Discretion
- Recipe list screen layout (grid vs list view)
- How to surface "Save as Recipe" action in EntryDetailScreen
- Recipe photo selection (if meal has multiple photos)
- How recipes appear in food search results (badge, section, or interleaved)
- Recipe re-log confirmation UI (minimal — should be 1-2 taps)

</decisions>

<code_context>
## Existing Code Insights

### Reusable Assets
- **custom_recipes + recipeIngredients tables** — already exist in schema (Phase 1)
- **FoodSearchScreen** — Phase 3.2 built search with history ranking, can integrate recipe results
- **EntryDetailScreen** — Phase 3.3 built full edit view, natural place for "Save as Recipe"
- **useFoodLogStore** — logScanResult pattern for creating diary entries from recipes
- **geminiNanoService** — can add recipe name suggestion to prompt

### Established Patterns
- Zustand stores, plain StyleSheet, op-sqlite, Drizzle ORM
- Stack navigation for new screens
- Bottom sheet for actions/confirmations

### Integration Points
- EntryDetailScreen → "Save as Recipe" action
- FoodSearchScreen → recipe results in search
- Recipe list → diary entry creation (re-log)
- Gemini Nano prompt → recipe name suggestion

</code_context>

<specifics>
## Specific Ideas

- "Save as Recipe" should be a single tap from the entry detail view — don't bury it in a menu
- Re-logging a recipe must be fast: tap recipe → confirm serving → done (1-2 taps)
- Recipe list should show usage frequency ("times used") to help users find their regulars

</specifics>

<deferred>
## Deferred Ideas

- Favorite recipes as quick-add cards on home screen (v1.1)
- Recipe sharing/export (post-v1.0)
- Nested recipes (recipes containing other recipes) — v1.1 feature per UI-05

</deferred>
