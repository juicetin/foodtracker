For each of the 8 screens, apply the identical migration pattern:

**Step A: Add theme import and hook call**
- Add `import { useTheme } from '../theme/ThemeProvider';` at top
- Add `const { colors } = useTheme();` as the first line inside the component function

**Step B: Convert StyleSheet to dynamic styles**
- Rename existing `const styles = StyleSheet.create({...})` at bottom of file to a factory function: `function createStyles(colors: ThemeColors) { return StyleSheet.create({...}); }`
- Import `ThemeColors` from `'../theme/colors'`
- Inside the component, add: `const styles = useMemo(() => createStyles(colors), [colors]);`
- Import `useMemo` from 'react' if not already imported

**Step C: Replace every hardcoded hex color with the corresponding semantic token**

Standard mapping (apply to ALL 8 screens):

| Hardcoded Hex | Replacement Token |
|---|---|

| `'#F9FAFB'` | `colors.background.surface` |

| `'#D1D5DB'` | `colors.border.default` |
| `'#E5E7EB'` | `colors.border.subtle` |

- `shadowColor: '#000'` -- shadows stay black in both themes
- `rgba(...)` values for overlays -- keep existing values
- Colors inside SVG/image assets (none expected)

**Step D: Handle inline style colors**
- For colors used in inline `style={{...}}` props (not in StyleSheet), replace directly with `colors.X`
- For colors passed to third-party components (Ionicons `color` prop, etc.), use `colors.X` directly

- **FoodSearchScreen** (49 occurrences): Has search input styling -- use `colors.input.*` tokens for input background/border/placeholder.
- **BarcodeScanScreen** (47 occurrences): Camera overlay colors may use rgba -- leave those as-is. Theme the UI chrome around the camera.
- **DiaryHomeScreen**: Mostly delegates to diary components (migrated in Plan 03), but has its own container/header styles.
- **DetectionScreen**: Has shimmer-related colors -- use `colors.shimmer.*` tokens.
- **InsightsScreen**: Chart/graph colors likely use accent colors -- map to `colors.accent.*`.
