# Phase 3.1: Daily Diary View + Macro Dashboard - Research

**Researched:** 2026-03-20
**Domain:** React Native UI — daily food diary with macro tracking, date navigation, swipe gestures
**Confidence:** HIGH

## Summary

This phase transforms the existing DiaryScreen from a basic meal-type-grouped list into a polished daily diary with time-period grouping (morning/afternoon/evening), prominent photo thumbnails, sticky macro dashboard header, swipe-based date navigation, and a week overview bar. The codebase already has a functional DiaryScreen with date navigation, entry cards, macro pills, trends, and an EntryDetailScreen for drill-down. The work is primarily UI refactoring and enhancement, not greenfield.

The existing stack (React Native 0.81, react-native-reanimated 4.1, react-native-gesture-handler 2.28, Zustand 5, op-sqlite) provides everything needed. No new dependencies are required. The key technical challenges are: (1) transitioning from meal-type grouping to configurable time-period grouping, (2) implementing the three-state tap expansion cycle on entry cards with visual affordance, (3) making the macro summary header sticky (pinned) within ScrollView, and (4) adding horizontal swipe gesture detection for date navigation.

**Primary recommendation:** Refactor DiaryScreen.tsx into smaller components (StickyMacroHeader, TimePeriodSection, ExpandableEntryCard, WeekOverviewBar, DateNavigator), add time-period configuration to usePreferencesStore, and use react-native-gesture-handler's Gesture API for swipe navigation.

### Pattern 1: Time-Period Assignment
**What:** Replace meal-type grouping (breakfast/lunch/snack/dinner) with time-period grouping (morning/afternoon/evening) based on entry's `created_at` timestamp.
**When to use:** Every diary view render.
**Example:**
```typescript
// services/diary/timePeriods.ts
export type TimePeriod = 'morning' | 'afternoon' | 'evening';

export interface TimePeriodBoundary {
  morning: number;   // hour (0-23), default 6
  afternoon: number; // default 12
  evening: number;   // default 18
}

export const DEFAULT_BOUNDARIES: TimePeriodBoundary = {
  morning: 6,
  afternoon: 12,
  evening: 18,
};

export function assignTimePeriod(
  createdAt: string,
  boundaries: TimePeriodBoundary = DEFAULT_BOUNDARIES,
): TimePeriod {
  const hour = new Date(createdAt).getHours();
  if (hour >= boundaries.evening) return 'evening';
  if (hour >= boundaries.afternoon) return 'afternoon';
  return 'morning';
}
```

### Pattern 2: Three-State Tap Cycle
**What:** Entry cards cycle through three states on tap: (1) macro summary line, (2) per-ingredient macro breakdown, (3) fully collapsed (title + photo only).
**When to use:** Each ExpandableEntryCard manages its own expansion state.
**Example:**
```typescript
type ExpansionState = 'summary' | 'ingredients' | 'collapsed';
const CYCLE: ExpansionState[] = ['summary', 'ingredients', 'collapsed'];

function ExpandableEntryCard({ entry }: { entry: DiaryEntry }) {
  const [state, setState] = useState<ExpansionState>('summary');

  const handleTap = () => {
    const idx = CYCLE.indexOf(state);
    setState(CYCLE[(idx + 1) % CYCLE.length]);
  };
  // ...
}
```

### Pattern 3: Sticky Header with ScrollView
**What:** Keep the macro dashboard pinned to top while scrolling entries.
**When to use:** The daily macro summary must always be visible.
**Implementation approach:** Use `stickyHeaderIndices` prop on ScrollView, or place the macro header outside the ScrollView in a fixed position above it. The simpler approach (macro header outside ScrollView) avoids `stickyHeaderIndices` complexity and works reliably.


### Pattern 4: Swipe Gesture for Date Navigation
**What:** Horizontal swipe left/right changes the selected date.
**When to use:** Wraps the ScrollView content area.
**Implementation:** Use react-native-gesture-handler's `Gesture.Pan()` with `activeOffsetX` threshold to avoid conflict with vertical scrolling.
```typescript
import { Gesture, GestureDetector } from 'react-native-gesture-handler';
import { runOnJS } from 'react-native-reanimated';

const SWIPE_THRESHOLD = 50;
const swipeGesture = Gesture.Pan()
  .activeOffsetX([-20, 20])    // Only activate for horizontal movement
  .failOffsetY([-10, 10])      // Fail if vertical movement is dominant
  .onEnd((event) => {
    if (event.translationX > SWIPE_THRESHOLD) {
      runOnJS(goToPreviousDay)();
    } else if (event.translationX < -SWIPE_THRESHOLD) {
      runOnJS(goToNextDay)();
    }
  });
```

### Pattern 5: Consumed/Remaining Toggle in Preferences
**What:** Persist the user's choice of showing consumed vs remaining macros.
**When to use:** StickyMacroHeader reads and toggles this preference.
**Implementation:** Add `diaryDisplayMode: 'consumed' | 'remaining'` to usePreferencesStore (already persisted via AsyncStorage).

### Anti-Patterns to Avoid
- **Do NOT use FlatList for time-period sections:** The diary has at most 3 sections with ~5-10 entries each. ScrollView is simpler and avoids FlatList nesting issues. FlatList only benefits lists with 50+ items.
- **Do NOT nest ScrollViews:** Use a single ScrollView for the entire diary content. The sticky header sits outside the ScrollView.
- **Do NOT make synchronous DB calls on main thread for date changes during swipe animation:** Load entries asynchronously after gesture completes, not during.
- **Do NOT duplicate date utility functions:** The existing `getTodayDateStr()`, `dateToStr()`, `formatDateLabel()` in DiaryScreen.tsx should be extracted to a shared utility, not re-implemented.

## Common Pitfalls

### Pitfall 1: Swipe Gesture Conflicts with ScrollView
**What goes wrong:** Horizontal swipe gestures intercept vertical scroll, making the diary unscrollable.
**Why it happens:** Without proper gesture configuration, Pan gestures consume all touch events.
**How to avoid:** Use `activeOffsetX` and `failOffsetY` on the Pan gesture to ensure horizontal movement must dominate before the gesture activates. Test on device -- emulator touch behavior differs.
**Warning signs:** Users can't scroll vertically, or date changes unexpectedly during scroll.

### Pitfall 2: Stale Entry Data After Date Change
**What goes wrong:** Entries show data from the previous date briefly after swiping.
**Why it happens:** The existing `loadEntriesForDate()` runs synchronous SQL, but state update + re-render creates a visible flash.
**How to avoid:** Update the date state and entries atomically. Consider showing a brief shimmer/skeleton during the transition, or preload adjacent days.
**Warning signs:** Flash of old content when changing dates.

### Pitfall 3: Time-Period Grouping vs Meal-Type Grouping Mismatch
**What goes wrong:** Entries logged with `autoDetectMealType()` have a `mealType` field, but grouping is now by `created_at` timestamp hour. An entry logged at 11:55am as "lunch" (mealType) would appear in "morning" (time period).
**Why it happens:** `autoDetectMealType()` uses hardcoded thresholds (10/14/17/21) different from time-period defaults (6/12/18).
**How to avoid:** Time-period grouping uses `created_at` hour, NOT `mealType`. The `mealType` field remains for backward compatibility but is not used for display grouping in the diary. Document this clearly.
**Warning signs:** User confusion about why an entry labeled "lunch" appears under "morning".

### Pitfall 4: Missing Photo Thumbnails
**What goes wrong:** Photo URIs from older entries may point to deleted files (cache cleared, app update).
**Why it happens:** Photos are stored as file:// URIs. iOS/Android can clean caches.
**How to avoid:** Use `Image` component's `onError` prop to show a placeholder when the photo file is missing. Use a food-themed placeholder icon (Ionicons "restaurant-outline").
**Warning signs:** Broken image icons in entry cards.

### Pitfall 5: Week Overview Bar Performance
**What goes wrong:** Loading 7 days of entry counts causes visible jank on date change.
**Why it happens:** 7 separate SQL queries (one per day) is naive.
**How to avoid:** Use a single SQL query with GROUP BY to load all 7 days' entry presence:
```sql
SELECT entry_date, COUNT(*) as count
FROM food_entries
WHERE entry_date BETWEEN ? AND ? AND is_deleted = 0
GROUP BY entry_date
```

## Code Examples

### Entry Loading with Time-Period Grouping
```typescript
// services/diary/diaryQueries.ts
// Extract from existing DiaryScreen.loadEntriesForDate, add time-period assignment
import { assignTimePeriod, TimePeriod, TimePeriodBoundary } from './timePeriods';

export interface DiaryEntry {
  id: string;
  timePeriod: TimePeriod;
  mealType: string;
  totalCalories: number;
  totalProtein: number;
  totalCarbs: number;
  totalFat: number;
  notes: string | null;
  createdAt: string;
  photoUri: string | null;
  dishes: DiaryDish[];
}

export function loadEntriesForDate(
  dateStr: string,
  boundaries: TimePeriodBoundary,
): DiaryEntry[] {
  // Same SQL as existing, but assign timePeriod from created_at
  const entryRows = opsqlite.executeSync(
    `SELECT id, meal_type, total_calories, total_protein, total_carbs, total_fat, notes, created_at
     FROM food_entries
     WHERE entry_date = ? AND is_deleted = 0
     ORDER BY created_at ASC`,
    [dateStr],
  ).rows;

  return entryRows.map((row) => {
    // ... photo + dish loading (same as existing)
    return {
      // ...existing fields
      timePeriod: assignTimePeriod(row.created_at as string, boundaries),
    };
  });
}
```

### Week Overview Bar Data Loading
```typescript
// Single query for 7-day entry presence
export function loadWeekEntryPresence(centerDate: string): Map<string, boolean> {
  const center = new Date(centerDate + 'T12:00:00');
  const startOfWeek = new Date(center);
  startOfWeek.setDate(center.getDate() - center.getDay()); // Sunday
  const endOfWeek = new Date(startOfWeek);
  endOfWeek.setDate(startOfWeek.getDate() + 6);

  const startStr = startOfWeek.toISOString().split('T')[0];
  const endStr = endOfWeek.toISOString().split('T')[0];

  const rows = opsqlite.executeSync(
    `SELECT entry_date FROM food_entries
     WHERE entry_date BETWEEN ? AND ? AND is_deleted = 0
     GROUP BY entry_date`,
    [startStr, endStr],
  ).rows as Array<Record<string, unknown>>;

  const presence = new Map<string, boolean>();
  rows.forEach((r) => presence.set(r.entry_date as string, true));
  return presence;
}
```

## Open Questions

1. **Should entries from before 6am (midnight-6am) be grouped under "evening" (previous day's period) or "morning"?**
   - What we know: Default boundaries are morning=6am. Entries between midnight and 6am have no defined period.
   - Recommendation: Assign them to "evening" since late-night eating is conceptually part of the previous day's evening. Make this configurable.

2. **How should the week overview bar handle the current week vs navigating to past weeks?**
   - What we know: Success criteria says "week overview bar showing which days have entries." The bar likely anchors to the week containing the selected date.
   - Recommendation: Week bar always shows the 7-day week (Sun-Sat or Mon-Sun per locale) containing the currently selected date. As user navigates past the week boundary, the bar updates to show the new week.
