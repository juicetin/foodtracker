# Phase 3.1: Daily Diary View + Macro Dashboard - Context

**Gathered:** 2026-03-20
**Status:** Ready for planning

<domain>
## Phase Boundary

Deliver the core daily diary screen users live in every day — chronological food entries with photo thumbnails, time-period grouping, always-visible macro summary, and date navigation. This is the primary screen of the app.

</domain>

<decisions>
## Implementation Decisions

### Time Period & Grouping
- Time period boundaries (morning/afternoon/evening) are user-configurable via settings
- Defaults: 6am–12pm (morning), 12pm–6pm (afternoon), 6pm–midnight (evening)
- Show per-period macro subtotals and daily totals

### Navigation & Interaction
- Date navigation supports BOTH swipe (left/right gesture) and button taps (prev/next arrows)
- Week overview bar shows all 7 days with visual distinction for empty days vs days with entries
- Entry expansion uses a three-state tap cycle: macro summary → per-ingredient macros → fully collapsed
- Include a visual affordance (e.g. dots indicator, subtle animation) explaining the cycle state

### Macro Dashboard
- Consumed/Remaining toggle preference persists across sessions (stored in preferences store)
- Daily macro summary header pinned to top of diary view (sticky header)

### Claude's Discretion
- Specific animation style for the three-state cycle indicator
- Exact layout/sizing of photo thumbnails in entry cards
- How to handle entries without photos (placeholder image vs text-only card)
- Swipe gesture sensitivity and animation curve

</decisions>

<specifics>
## Specific Ideas

- The existing DiaryScreen uses meal-type grouping (breakfast/lunch/snack/dinner). The success criteria specify time-period grouping (morning/afternoon/evening). These are different — need to transition from meal-type to time-period or support both.
- Photo thumbnails are the product's differentiator — they should be prominent in entry cards, not tiny afterthoughts.
- The three-state tap cycle (summary → ingredients → collapsed) is a non-standard interaction. The visual affordance must be discoverable — consider a brief tooltip on first use.

</specifics>
